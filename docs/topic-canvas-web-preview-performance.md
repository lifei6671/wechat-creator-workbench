# 专题画布网页预览性能实测

Windows 11 Release 构建在 60 Hz 下的四组场景中，连续缩放帧间隔 P95 均为 **16.8 ms**，达到方案的 20 ms 目标。单张网页激活时，从第一条滚轮输入到首个视口更新的 P95 由 **102.1 ms 降到 28.6 ms**。

## 环境与方法

- Windows 11 专业版（26200）、WebView2 157.0.4341.46、RTX 4070 SUPER，应用客户区为 1360 × 840 CSS px。基线和改造后的 Release 构建共用隔离测试库与本机 HTTP 测试页。
- 在系统原生 150%（应用 DPI 144）和应用兼容 100%（应用 DPI 96、WebView2 DPR 1）分别测试。100% 通过进程级 DPI 兼容设置实现，物理显示器仍为 150%。
- 每个场景连续输入 120 条交替放大、缩小的滚轮事件，间隔约 8 ms，重复五轮。帧间隔来自画布主视图的 `requestAnimationFrame`，锚点来自 React Flow 的视口矩阵。100 节点场景中的 30 个图片节点复用同一张测试 PNG。
- 另用 Win32 滚轮事件验证窗口输入路径，两种 DPI 下各记录到 36 次视口变化，倍率从 66% 到约 230% 后回到 66%。以桌面像素采样和 30 fps 窗口录像验证原生网页的遮挡与恢复。

## 连续缩放结果

| 场景 | 基线帧间隔 P95 | 改造后 P95（150% / 兼容 100%） | 150% 下每轮视口变更中位数 |
| --- | ---: | ---: | ---: |
| 20 个文本节点 | 16.8 ms | 16.8 / 16.8 ms | 73 → 58 |
| 100 个节点，含 30 个图片节点和 100 条连线 | 16.8 ms | 16.8 / 16.8 ms | 73 → 57 |
| 10 个静态网页卡片 | — | 16.8 / 16.8 ms | 58 |
| 1 个实时网页，另有 9 个静态网页卡片 | 16.8 ms | 16.8 / 16.8 ms | 68 → 56 |

基线的 10 个网页节点中有 1 个自动加载的实时网页，其余仅显示 URL。实时网页场景的末次滚轮输入到最后一次视口更新 P95 由 **265.7 ms 降到 10.1 ms**。四组场景的固定锚点漂移实测均低于 0.01 CSS px。

| 时间指标 | 样本 | P50 | P95 | P99 |
| --- | ---: | ---: | ---: | ---: |
| 150% 下选中无缓存网页到首次显示有效 PNG | 10 | 204.9 ms | 222.6 ms | 222.6 ms |
| 150% 下结束滚轮输入到实时网页恢复显示 | 5 | 421.7 ms | 433.0 ms | 433.0 ms |
| 兼容 100% 下结束滚轮输入到实时网页恢复显示 | 5 | 428.7 ms | 442.0 ms | 442.0 ms |

恢复时间包含 350 ms 手势结束判定。150% 下的 186 个采样点和兼容 100% 下的 180 个采样点均未出现白色或标记错位。采样检查的是网页中锚定到同一桌面坐标的颜色标记。五轮缩放前后的网页滚动位置、视口宽度与测试段落宽度一致。

## 原生交互、缓存与清晰度

- 两种 DPI 下均通过网页内真实鼠标点击及原生焦点下的 Escape 测试。关闭再进入专题后，从磁盘恢复 10 张 PNG，且没有实时网页。删除激活卡片后，原生视图关闭，该卡片的 PNG 从 18,681 字节变为 0，其他卡片的 7,687 字节 PNG 保留。删除专题后，该 PNG 也被清除。
- 测试卡片内容区为 284 × 162 CSS px。原生截图尺寸如下。

  | 画布倍率 | Windows 150% | 应用兼容 100% |
  | --- | ---: | ---: |
  | 10% | 44 × 25 px | 28 × 16 px |
  | 100% | 426 × 243 px | 284 × 162 px |
  | 300% | 1278 × 729 px | 852 × 486 px |

- 从 100% 放大到 300% 时，`innerWidth` 和滚动位置保持稳定，测试段落宽度增加约 9 CSS px。10% 下，150% 和兼容 100% 模式的 `innerWidth` 分别为 290 和 224 CSS px，回到 100% 后滚动位置分别偏移 2 和 3 CSS px。保留现有 PNG 捕获方式，独立高清采样及分级缓存未启用。
- 首帧筛查检查 PNG 可见内容的对比度，并排除右侧和底部滚动条。完全纯色、极低对比度或内容仅落在裁剪区内的页面可能继续显示占位。
- 测试页先绘制纯色背景，1.8 秒后显示正文。选中后 2.925 秒显示首张有效 PNG，加载背景未保存为预览。仅在左上角显示一行状态文字的测试页也能生成预览。
- 原生截图和缓存生成仅在 Windows 验证。macOS 和 Linux 沿用原有子视图交互入口，本轮未运行这两个平台的桌面构建。

## 实现范围与时序

- `CollectionCanvas.tsx` 以节点和连线选中态推导激活网页。粘贴先处理待保存的编辑，再原子提交新卡片和单选状态。滚轮输入按帧合并并使用最后的指针锚点。
- `CollectionNodes.tsx`、`collection-canvas.css` 和 `CanvasPreviewCache.ts` 负责静态预览和对象 URL 生命周期。`CanvasWebPreview.ts` 串行遮挡旧视图、刷新原卡片截图、关闭旧视图，再打开最新选中的网页。连续输入期间冻结实时视图，手势结束后更新一次边界并等待有效画面。
- `desktop.ts`、`canvas_webview.rs`、`canvas_preview_cache.rs`、`commands.rs` 和 `content/collections.rs` 负责二进制截图、磁盘持久化、归属校验与删除。`main.rs`、`build.rs` 和 `capabilities/desktop.json` 完成命令注册与授权。回归覆盖位于 `collection-canvas.test.tsx` 及对应 Rust 模块。
