## 已确定的技术决策

- **产品**：微信公众号写作与灵感收集工作台；借鉴 Obsidian 的侧边栏、编辑区、标签页等交互方式。
- **数据库**：SQLite 保存 Markdown 正文及文章元数据；图片存储在本地文件系统，采集后的公众号文章仅保留清洗后的 Markdown 和来源信息。
- **桌面**：Tauri 2 + React + TypeScript + Rust；使用 Milkdown 富文本编辑和 Markdown 持久化。
- **技术复用**：从 [Plainly](https://github.com/lifei6671/plainly) 选择性抽取 Markdown 渲染、主题注册、公众号排版与图片识别逻辑，不沿用其整套应用壳层。
- **公众号**：富文本复制和图片持久性必须通过真实公众号草稿保存、重新打开验证。
- **资料管理**：灵感、资料、文章三类内容，以素材、分类、标签和来源关联。
- **专题画布**：专题以 React Flow 展示文章引用、截图和临时文案；文章引用全局内容库，图片和文本逻辑归属当前专题；画布节点与连线独立于正文编辑保存。
- **GitHub 导入**：公开仓库默认 README 导入为 reference，保留来源元数据并可加入专题。
- **备份与集成**：S3 图床独立于仅备份 SQLite 数据库的 S3 备份/恢复；本地 Streamable HTTP MCP 完整保留；用户自配模型接口。
- **历史版本**：日常自动保存只更新当前正文；仅手动关键版本及 AI 整篇覆盖前保留历史，每篇最多 3 条。
- **保存与异步操作**：每篇文章串行保存；AI 改写、异步插图和渲染结果绑定发起时的文章与输入，不覆盖后续修改或其他文章。
- **图片删除**：编辑和撤销期间只更新引用，决定实际退出时按内容哈希组先删全部已登记 S3 目标、再删本地文件；正文、封面、保留历史、软删除内容及派生源片段仍引用时保留。部分失败保留未完成项，重新引用取消整组清理；取消退出保留撤销会话，取消清理则继续退出。专项验收见实施计划第 10.3 节。
- **数据库恢复**：校验后重启替换，重建编辑状态并停止旧任务；恢复触发的重启不执行图片清理。
- **图片恢复边界**：S3 数据库备份不含本地图片；远程图床有可用对象时可通过数据库映射加载。
- **导出**：HTML 与 Markdown 带图导出包含独立素材，后续清理源图片不影响已经导出的文件。
- **实现约束**：禁止防御性编程，不为几乎不可能发生的边界增加兜底、重复校验或恢复框架；处理当前实际流程与明确失败。
- **开源**：仓库现有 GPL-3.0 许可证；引入第三方主题及代码时核对并保留许可与署名。

## 开发入口

按 [实施计划与验收](./implementation-plan.md) 从 P0 工程底座、P1 内容管理与编辑保存开始，再完成素材、导入排版、MCP/AI 和备份恢复。直接开发正式应用，不以前置原型或公众号兼容报告作为开工关卡。

开发期间保留构建、类型检查及必要局部测试；完整黄金样例、集中回归和发布构建放在 P6，端到端测试的搭建与执行、跨平台和真实服务验收统一放到最后的 P7。图床连接测试和数据库完整性检查等产品功能按所属阶段实现。

实现代码与设计文档应保持同步；涉及存储格式、协议接口和数据迁移的修改，先更新技术方案及相关验收项。
