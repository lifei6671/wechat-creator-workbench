# 微信创作工作台 MVP 技术方案

> 项目：wechat-creator-workbench  
> 版本：1.3（核心功能优先，验证后置，技术栈与 MVP 范围不变）
>
> 日期：2026-11-15  
> 目标：以本地优先方式，为微信公众号作者提供灵感收集、资料导入、Markdown 写作、公众号排版和内容资产管理能力。  
> 开源协议：GPL-3.0（当前仓库许可证）。  
> 配套实施与验收：[implementation-plan.md](./implementation-plan.md)

## 1. 定位与边界

### 1.1 典型用户与核心路径

主要用户：独立微信公众号作者、技术博主、习惯 Markdown 的内容创作者。安装即可离线使用；S3、AI、MCP 配置均为可选增强项。

核心闭环：

1. 通过收集箱记录选题、观点、链接、截图。
2. 将公开微信公众号文章导入资料库，提取正文与元信息，下载图片到本地。
3. 从灵感/资料创建文章，在 Markdown 编辑器中撰写、插图、自动保存与检索。
4. 选择公众号排版主题，实时预览，检查图片与特殊元素。
5. 复制适配公众号的富文本，粘贴到公众号后台；保存草稿并验证图片，记录发布状态和原文链接。
6. 使用 S3 备份、恢复 SQLite 数据库；图片由本地与独立图床管理；允许外部 Agent 经本地 HTTP MCP 操作内容。

### 1.2 内容模型

统一内容实体 Entry，通过 kind 区分：
- idea（灵感）：允许无标题、短正文，支持转换为文章。
- reference（资料）：只保存导入后**清洗的 Markdown**、标题、原文链接、公众号名称、作者及发布时间；不保存原始 HTML 或抓取前原文版本。
- article（文章）：Markdown 正文、分类、标签、摘要、封面、公众号主题、发布状态及发布链接。

从资料或灵感创建文章时，生成新的 Entry，并通过 entry_links 记录来源；不自动保存原网页快照，也不建立多套历史记录。

状态按 kind 约束：idea 使用 inbox / planned / used / archived；reference 使用 unread / reviewed / used / archived；article 使用 draft / ready / published / archived。创建时由业务服务设置初始状态，不设置跨类型的默认 draft。

### 1.3 MVP 功能与阶段范围

| 能力 | MVP 最低交付 | 后续扩展 |
| --- | --- | --- |
| 写作 | 富文本编辑、只读阅读、公众号实时预览、快捷键、查找替换、自动保存、多标签页 | 复杂插件 |
| 内容 | 收集箱、资料库、文章库、二级分类、标签、全文搜索、内容关联 | 双向链接知识图谱 |
| 图片 | 粘贴/拖拽、本地落盘、哈希去重、图片预览、S3 图床 | 素材批量加工、云端同步 |
| 排版 | 主题选择、公众号预览、CSS 内联、富文本复制、图片处理、HTML/Markdown 导出 | 微信公众号官方草稿接口 |
| 导入 | 单个公开微信文章 URL、清洗的 Markdown 与图片、来源信息、失败诊断 | 批量导入、浏览器扩展 |
| 数据 | SQLite 正文存储、少量关键历史版本、S3 数据库单文件备份与恢复 | 多端双向同步、素材备份 |
| MCP | 本地 Streamable HTTP、搜索/读取/创建/修改、鉴权与版本冲突 | 远程安全访问 |
| AI | 用户自配模型、总结、标题建议、选区改写与差异确认 | 多智能体、语义搜索 |

明确范围：Windows 11 和 macOS 桌面应用；无注册、无独立业务服务器、无托管云账户；公开文章导入不尝试自动绕过平台验证；微信公众号发布以复制到后台为主，首版不承诺自动发布。

### 1.4 实现约束

禁止防御性编程：不为几乎不可能发生的情况增加分支、兜底、重复校验或恢复框架。实现只处理当前产品中的实际流程，例如连续编辑、异步结果返回、删除后撤销、断网、S3 操作失败和用户主动恢复数据库。输入校验放在真实入口，内部复用已有保证；失败明确反馈，重试复用现有任务机制，不增加分布式协调、多代数据副本或通用状态机。

### 1.5 实施顺序

先完成 P0 工程底座、P1 内容管理与编辑保存、P2 素材与 S3 图床、P3 Plainly 排版与导入发布、P4 MCP/AI、P5 SQLite 备份恢复，再做 P6 集中回归与发布构建，最后做 P7 端到端验收与发布。完整 Plainly 主题和公众号转换在 P3 接入，不阻塞前面的基本写作功能。

不设置独立技术验证原型、完整黄金样例或公众号兼容报告作为核心功能开发的前置关卡。开发中保留构建、类型检查和必要的单元/组件测试；集中回归与性能验证在 P6 进行，端到端测试的搭建和执行、跨平台及真实公众号/S3/MCP/模型接口验收统一放到 P7。图床连接测试、数据库完整性检查等产品行为仍随所属功能实现。

## 2. 核心架构决策

### 2.1 存储：SQLite 为正文唯一数据源

- Markdown 正文、分类、标签、来源元信息、内容状态与任务存入 SQLite；.md 文件是手动导出产物，不是双向同步的数据源。
- 图片及附件保存在本地 assets/ 目录，文章用稳定的 asset:// 资源标识引用；S3 图床上传单独运行，数据库保留 object key、公开地址和上传状态。
- **S3 数据备份仅上传 SQLite 的一致性数据库快照**，不包含图片、附件、原始页面或完整工作区包。S3 图床与数据库备份是两个独立功能。
- 从公众号抓取文章只存清洗后的 Markdown 和来源元数据。HTML 解析过程的原始正文在转换后释放。
- 日常自动保存仅更新当前正文，不创建历史快照。仅手动保存版本、AI 整篇重写前可记录关键版本，每篇最多保留最近 3 条。
- 删除正文图片只更新引用；正常退出应用时，按第 6.4 节统一清理无引用素材的本地文件和应用上传的 S3 对象，保留当前编辑会话的撤销能力。
- WAL 和事务保证数据库内部一致性，所有写入经统一 Rust 应用服务完成。
- **数据库恢复不等于图片恢复**。已上传图床的素材可以根据数据库远程映射重新访问；仅存在本地的素材在换设备后将显示缺失。

~~~text
workspace/
  content.db              # Markdown、元信息、索引、任务和版本
  assets/
    ab/cd/<hash>.png       # 本地图片及附件，不进入 S3 数据库备份
  backups/
    staging/              # 临时数据库快照与恢复文件
  logs/                   # 本地日志
~~~

### 2.2 技术栈

| 层 | 推荐技术 | 职责 |
| --- | --- | --- |
| 桌面运行时 | Tauri 2 / Rust | 系统文件、剪贴板、数据库、S3、任务、MCP 服务 |
| 前端 | React + TypeScript + Vite | Obsidian 式操作布局与交互 |
| 编辑器 | Milkdown / ProseMirror | Markdown 双向转换、富文本编辑、快捷键、选区、滚动映射 |
| 主题与排版 | Plainly 选择性抽离，markdown-it、juice | Markdown → HTML → 公众号富文本 |
| 本地数据库 | SQLite + rusqlite | 事务、关系、版本、FTS5 检索 |
| HTTP / 网络 | Rust reqwest + Axum | 公众号文章下载、AI 调用、本地 MCP |
| MCP 协议 | 官方 Rust SDK rmcp，接入 Axum | Streamable HTTP 协议与协商；业务规则仍在应用服务 |
| S3 | AWS SDK for Rust（S3 兼容） | 对象上传/下载、备份恢复 |
| UI 状态 | 轻量 React 状态层（可选 Zustand） | 标签页、当前草稿、界面布局 |
| 机密 | 操作系统安全凭据存储 | S3 与模型 API 密钥 |
| 质量 | Rust 单元/集成测试 + 前端组件测试 + E2E | 领域规则、复制与恢复回归 |

沿用 React 和 TypeScript 复用 Plainly 排版能力。正文编辑器使用 Milkdown 和 ProseMirror，编辑事务经过 Markdown 序列化再进入既有 SaveQueue。

### 2.3 组件分层

~~~mermaid
flowchart TB
  UI["React 桌面应用<br/>收集箱 / 资料 / 文章 / 编辑器 / 排版预览"]
  EDIT["editor-react<br/>Milkdown / ProseMirror"]
  RENDER["markdown-core + wechat-renderer<br/>解析 / 主题 / HTML / 导出"]
  IPC["Tauri IPC 命令"]
  MCP["本地 Streamable HTTP MCP"]
  APP["Rust 应用服务层<br/>Entry / Category / Asset / Import / Backup / AI"]
  DB["SQLite"]
  FS["本地素材文件"]
  S3["S3 图床与备份"]
  UI --> EDIT
  UI --> RENDER
  UI --> IPC
  MCP --> APP
  IPC --> APP
  APP --> DB
  APP --> FS
  APP --> S3
~~~

关键边界：
- 前端编辑器只接收 value、onChange、onPasteImage、onDropImage 和编辑命令，不直接保存数据库，也不直接持有图床凭据。
- 领域服务是统一写入入口；Tauri IPC 与 MCP 共用业务校验、事务、版本规则。
- Markdown 渲染/主题为可独立测试的 TypeScript 包。MCP 首版只提供内容读写与检索，不要求 Rust 直接运行浏览器 DOM 排版；后续若提供无界面渲染，须加入独立渲染执行器或可验证的版本缓存。
- 网络下载图片统一由受控资源服务执行，不能将任意来源网址直接映射到本机文件或内网。
- 同一工作区由一个桌面进程管理；重复启动聚焦已有窗口，复用 Tauri 的单实例能力，不另建跨进程任务协调。

## 3. Plainly 复用与重构

P3 采用 [Plainly 固定提交](https://github.com/lifei6671/plainly/tree/73d906300817523b313f96d5acbbbbd96f23fbb4) 的三套 Rico 微信主题，来源、许可和迁移处理见 [排版来源](../packages/wechat-renderer/SOURCES.md)。

已核对的模块与迁移策略：

| Plainly 路径 | 价值 | 处理方式 |
| --- | --- | --- |
| src/theme/registry.ts、types.ts、normalizer.ts | 主题注册与标准化 | 复用思路及实现，改用稳定 themeId |
| src/theme/component/transformer.ts | 组件级 HTML 结构变换 | 抽离，解除主页面 DOM / 滚动依赖 |

| src/utils/helper.ts 中 markdownParserWechat 等 | Markdown 扩展与代码高亮 | 抽离渲染核心，配置注入 |
| src/utils/converter.ts | CSS 内联、微信公式、表格修正 | 抽象 render(markdown, theme) 输出，不读固定 DOM ID |
| src/utils/imagePaste.ts、imageCompress.ts | 粘贴识别、图片压缩 | 保留算法，分离网络下载与素材入库 |
| src/utils/syncScroll.ts | 按标题锚点的双栏滚动同步 | 重构为独立视图适配器 |
| src/layout/MarkdownEditor.tsx | 编辑器交互参考 | Milkdown 富文本编辑层 |

| src/data/store/IDataStore.ts | 数据接口设计经验 | 替换为按领域的 Repository / Service |
| src/data/store/browser/BrowserDataStore.ts、src/server/** | 旧存储与服务模式 | 不作为新桌面应用基础 |
| src/App.tsx、src/store/** | 现有页面逻辑 | 仅保留用户流程，重建 UI 状态边界 |
| src-tauri/** | Tauri 1 经验 | Tauri 2 独立初始化与权限配置 |

明确的耦合修复项：
1. MarkdownEditor 目前直接依赖 MobX content 及 uploadAdaptor；改为受控编辑器和独立图片导入回调。
2. converter 目前从固定 LAYOUT_ID/主题 DOM 读取 HTML 与 CSS；改为参数输入、隔离渲染容器和纯净的结果对象。
3. imageHosting 目前包含通知、配置、上传、图片插入及 Tauri IPC；拆为 ImageProcessor / AssetService / S3StorageProvider / AssetUrlResolver / EditorImageExtension。
4. 旧 ContentStore 中正文变更同时写配置存储；改为内存编辑缓冲 + 异步保存 Service。
5. 主题持久化使用 themeId 而不是 templateNum 数组位置，兼容主题增删和排序。
6. 用行为测试确认富文本编辑器的选区、撤销、查找和剪贴板契约。

### 3.1 渲染与导出的完成条件

- 解析和主题变换与 DOM 排版分开；DOM 排版使用隔离容器，保留计算样式所需的实际布局，不把移除固定 DOM ID 等同于已经消除浏览器依赖。
- 排版入口异步返回结果。复制或导出开始时固定正文、themeId 和输出模式，等待该输入的公式、Mermaid、图片尺寸及字体就绪，再内联 CSS、转换素材并生成结果；所需渲染资源随应用提供，支持离线预览。
- 结果包含输入修订标识、HTML、依赖素材与警告。预览只接受当前输入的结果；复制使用点击时的输入快照，不在任务中途读取另一篇文章或新主题。失败时报告失败，不把上一次成功结果冒充本次结果。

### 3.2 预览安全边界

公众号导入先净化原始 HTML；编辑器、MCP 与导入内容统一经过渲染输出净化，任何不可信 HTML 插入预览 DOM 前均执行同一允许列表规则。规则覆盖标签、事件属性和资源 URL，保留排版所需元素，不仅清理导入入口。图片 URL 交由资源服务解析，不通过原始 HTML 绕过下载约束。Tauri 权限配置同时覆盖插件与自定义 IPC 命令，不向文章内容开放脚本或命令执行能力。

**许可证**：新仓库已有 GPL-3.0。复用 Plainly 源码时保留对应版权/许可文本；仓库中部分 Rico 上游主题标为 MIT，部分公众号主题标为 AGPL-3.0-or-later，应逐模块登记来源、版本、许可及分发义务。首个主题包优先选择许可已核实的资源；AGPL 主题的组合分发与声明在纳入前完成许可审查。

## 4. 核心数据模型

### 4.1 表与数据权威性

| 表 | 关键字段或职责 |
| --- | --- |
| entries | id, kind, title, content_md, status, category_id, source_id, summary, cover_asset_id, theme_id, version, created_at, updated_at, published_at, published_url, deleted_at |
| categories | id, parent_id, name, depth, sort_order；最多两级 |
| tags / entry_tags | 标签定义及条目关联 |
| entry_links | 灵感、资料与文章的来源关联 |
| sources | id, source_url（规范化后唯一）, author, account_name, original_published_at, imported_at；同一来源由一条资料通过 source_id 引用，文章使用 entry_links 关联该资料。不存 HTML |
| assets | id, sha256, mime_type, relative_path, kind(original/derived), source_key, bytes, created_at, retain_on_exit；直接导入素材库的图片设置 retain_on_exit；source_key 仅派生图片使用；未下载图片允许 sha256 / mime_type / relative_path / bytes 为空 |
| entry_assets | 正文图片引用的**派生索引**，保存时由 Rust 重建；封面以 entries.cover_asset_id 为准，不混入导出结果状态 |
| storage_profiles / asset_locations | 存储配置；按 sha256 关联应用上传对象的准确存储目标、object key、公开 URL 与上传/删除状态；同一哈希和目标仅一条位置记录 |
| asset_urls | 登记过的图床公开地址与实际远端位置的关联。变更公开访问地址时保留旧地址供正文和历史判断引用，远端可用性以 asset_locations 为准 |
| entry_revisions | 少量关键版本：entry_id, version, content_md, reason, created_at |
| jobs | 上传、采集、AI、素材清理任务状态及失败信息；素材清理按 sha256 复用一条未完成任务；导入补图记录目标 entry_id、asset_id、原图片 URL，不保存原始 HTML |
| wechat_sources | 规范化的公众号分享地址、实际访问地址和规范来源 URL 别名，指向同一资料 |
| backup_records | S3 数据库备份操作记录；备份列表以 S3 实际对象为准 |
| app_settings / entries_fts | 普通设置、稳定 workspace_id 和 FTS5 搜索；workspace_id 随数据库备份恢复 |

entries.content_md 是正文内容与正文图片引用的权威数据；entry_assets 每次正文提交时由 Rust 提取并在同一事务中更新，不接受前端清单作为权威结果。封面通过 cover_asset_id 维护。清理按第 6.4 节执行，检查全部条目的正文、封面及保留历史引用；仍可恢复的软删除条目同样计入，不另建 revision_assets 表。

前后端约定相同的资源语法：支持内联图片、引用式图片，以及允许列表中的 HTML img src；普通代码块、行内代码和转义示例不算图片引用。正文写入已登记的图床公开 URL 时，也按 asset_locations 映射计入素材引用，不能只识别 asset://；其他外部图片 URL 不代表应用有权删除其源对象。Rust 使用现有 Markdown 解析器提取资源，不重做主题排版；TypeScript 渲染器与 Rust 提取器共用语法样例、预期 asset ID 和公式/Mermaid 源片段 key。远程图片仍交由受控资源服务处理。

### 4.2 数据库约束与迁移

- 主键使用 UUID/ULID；时间统一为 Unix 毫秒；外键开启。
- 分类 depth 只能为 1 或 2，父分类必须属于一级，同级名称唯一。
- entries.kind 与 status 的合法组合在数据库 CHECK 和 Rust 业务服务中约束：灵感(inbox/planned/used/archived)、资料(unread/reviewed/used/archived)、文章(draft/ready/published/archived)。
- 首批 SQL migration 应完整定义 entries、categories、tags、entry_tags、entry_links、sources、assets、entry_assets、storage_profiles、asset_locations、entry_revisions、jobs、backup_records 与 app_settings；FTS5 索引可重建。
- 公式与 Mermaid 仅在导出需要转为图片时创建 kind=derived 素材，原 Markdown 保留源码。派生素材的 source_key 由源片段类型和源码计算，不包含整篇正文或主题；退出时解析当前正文及保留历史中的源片段，仍存在相同 source_key 就保留对应图片。改其他段落、切换主题、重新导出不会立即删除旧派生素材，删除源片段后再撤销也能保留原图。仅在源片段已无引用、且图片没有直接引用时清理；源片段仍在时允许保留其已生成的主题版本，不增加“最近有效导出”记录或版本淘汰机制。输出对应性仍由第 3.1 节的输入快照保证。

### 4.3 自动保存、少量历史和冲突

- 编辑内容约 500～1000ms 防抖保存，切换文章/失焦时提交；界面提示保存中、已保存或失败。
- 每篇文章最多一个在途保存请求；请求期间的新输入合并为最新待保存内容，收到成功响应后用新 version 继续提交。编辑缓冲使用本地修订号标识，旧响应不回填覆盖新输入，只有最新修订提交成功才显示已保存。失焦、切换和正常退出复用同一保存队列。
- **自动保存不产生历史全文快照，也不设置定时快照。** 仅在用户主动保存关键版本、AI 整篇改写前保留版本，最多 3 条；选区改写使用编辑器撤销。
- SQLite 更新使用 expectedVersion 乐观锁。冲突后停止该条目的自动提交，内存中保留正在编辑的内容，允许复制当前内容、另存草稿或重新加载最新数据库正文；MCP 返回 VERSION_CONFLICT 和当前版本号。
- 不实现自动三方合并、长期编辑缓冲镜像或额外的崩溃恢复数据库；只保证成功提交的正文。
- 素材先落盘，再写入索引；正文自动保存只维护引用，不删除本地文件或 S3 对象。会话期间保留待插入、撤销可能用到及导出中的素材，统一在正常退出时判断是否无引用。

### 4.4 搜索

使用 SQLite FTS5 trigram 及分类/标签过滤。搜索框默认按普通文本处理，不把用户输入直接解释为 FTS 查询语法；不足 3 个 Unicode 字符的关键词用参数化 LIKE 回退，并按字面处理通配字符。明确包含一字、两字词、标点、中英混合及分类/标签组合过滤的样例；以 1000 篇约 5000 字文章并含 5 万字长文作为首版验收样本，记录查询耗时，搜索不阻塞编辑。首版不引入向量数据库或分词服务。

## 6. 图片与 S3 图床

### 6.1 资源处理

- 从粘贴、拖拽或公众号文章清洗过程接收图片。校验基本类型与大小、计算 SHA-256、按哈希在 assets/ 保存并复用，生成 asset://<id> 资源标识。
- P2 支持 PNG、JPEG、GIF 和 WebP。单张最多 20 MB，单边最多 16,000 像素，总像素最多 4,000 万。
- 同一字节内容可以因导入占位或派生来源拥有不同 asset ID，但只存一份哈希文件；S3 对象同样按工作区、存储目标和哈希去重。引用与清理统一按 sha256 归组，不能只检查某一个 asset ID。
- 本地图片优先用于离线预览。配置 S3 图床后异步上传，发送请求前先登记准确存储目标和确定性 object key，成功后更新公开 URL 与可用状态；失败或取消仍保留目标记录，供后续重试或清理。上传失败不影响 Markdown 保存。
- 图床上传和数据库 S3 备份彼此独立：备份流程不收集图片文件。
- 若恢复 SQLite 后发现本地图片不存在，可根据已存图床地址尝试远程加载；没有远程副本则提示缺失。
- 正文预览通过素材服务读取本地图片和已登记图床副本。普通外部图片地址显示缺失占位，网页图片采集随 P3 接入。
- S3 图片对象放入本应用工作区专属前缀，删除使用 asset_locations 中记录的准确目标和 object key，不根据公开 URL 猜测路径，不删除公众号来源站点上的原图。
- 图床连接测试使用本应用创建的测试对象验证上传、读取和删除权限。更换 endpoint、bucket 或对象前缀时使用新配置，保留仍有未删除对象映射的旧配置及凭据引用；可以更新旧密钥，但不能直接删除仍被这些映射使用的配置。只修改公开域名不改变对象存储目标。

### 6.2 导出与发布模式

- Markdown 导出将逻辑图片 URI 改为相对路径；用户可以选择单篇 .md 或带图片的导出包。导出不改写正文和文章版本；需要生成派生图片时只登记素材信息。
- 带图 Markdown 包包含正文与 assets/，单篇 .md 的本地图片写到同级配套目录。HTML 导出提供带内联 CSS 的 .html 与相对 assets/ 目录，带图时打包下载；两种导出均复制素材，不依赖日后仍存在的应用素材目录或 S3 URL。仅有远程副本时通过资源服务下载，缺失或下载失败明确报告，不把缺图结果标记为完整导出。
- 公众号**纯排版复制**：处理无图片内容，直接复制带内联 CSS 的 HTML。
- **无图床的图片辅助发布**：展示正文图片顺序，提供逐张复制/保存功能，用户在公众号后台上传或插入。
- **图床整篇复制**：先保证图片已有稳定可公开访问的 S3 URL，再将 HTML 里逻辑 URI 替换后复制；最终效果以微信公众号后台保存草稿并重开为准。
- 公式和 Mermaid 输出公众号图片时进入同一个素材管线，生成的内容视为 derived 素材，不改写原始 Markdown。

### 6.3 P7 最终兼容验收

核心功能完成后，使用候选安装包验收第 6.2 节既定的公开图床 URL 整篇复制和无图床逐图辅助发布。记录系统、浏览器、图床域名类型（例如 R2 自定义域名、OSS 公网域名）、图片数量、防盗链或可达性，以公众号后台保存并重新打开后的结果判定，不能以剪贴板 API 成功代替实际成功。

仅当既定路径出现实际兼容问题时，针对问题比较 HTML + Base64、HTML + PNG 剪贴板、多个 ClipboardItem 等候选方案；不预先穷举，也不在功能开发前建立多套备用实现。修复后重测受影响流程。

同时验证输入公式后立即复制、切换主题或文章后立即复制，确认等待渲染完成且输出与本次输入一致。HTML / Markdown 文件导出另以普通浏览器或阅读器离线打开验收。

### 6.4 图片删除与撤销

**清理时点固定为正常退出应用时，清理单位为内容哈希组。** 删除正文图片、替换封面及自动保存仅更新引用；编辑期间本地与 S3 都不物理删除。切换或关闭单个标签不触发清理；撤销能力遵循编辑器会话，不承诺关闭标签或重启后的编辑撤销，不增加素材回收站或定时回收设置。

从素材库选择文件或拖入的图片设置保留标记，正常退出时保留其哈希组。此前没有记录导入渠道的原图随迁移保留。正文粘贴、编辑区拖入、外链自动保存及排版派生图片继续按引用判断。

1. **准备退出。** 暂停新的编辑、MCP 写请求和任务，停止后台结果继续改正文，完成保存队列。保存失败或用户取消退出时，保留正文缓冲和撤销历史，恢复编辑与服务，不执行清理；已停止的后台任务保持可重试，不自动重发 AI。只有稿件保存完成或用户明确放弃未保存内容，并决定实际退出后，才结束编辑会话。
2. **停止素材任务并计算引用。** 取消尚未发送的排队上传，沿用已有取消/等待机制结束在途素材任务；若仍有会写素材的任务未停止，或已发送的上传未正常结束，本次直接跳过整轮清理，保留已登记目标到下次退出处理。任务结束后，按最终已提交数据库一次性计算引用：所有正文、封面、保留关键历史、可恢复软删除条目，以及第 4.2 节派生源片段。组内任一 asset ID 或源片段仍被引用就保留整组，清理期间不重新开放业务写入。
3. **先远程、再本地。** 无引用哈希组复用一条清理任务，逐个删除 asset_locations 中尚未完成删除的目标，包括上传失败但可能已产生对象的目标；同一目标只处理一次。每个目标成功后单独记录已删除，只有所有远程目标均完成，才删除该组本地文件；本地成功后移除该组 assets 和位置记录，将清理任务记完成，取消该组未发送的上传和过期补图项，不移除同一导入任务的其他结果。没有远程目标时直接处理本地。无文件的未引用占位只移除记录及对应补图项，不发送 S3 请求。
4. **失败只保留未完成项。** 任一远程删除失败时保留本地文件及映射；本地删除失败时也保留素材记录，下一次只补本地删除。已成功的远程目标不能再提供为可用图床地址。每次退出只尝试一轮，沿用现有超时；允许取消剩余清理并直接退出，取消清理不等于返回原编辑会话。不存在的目标视为该项已完成，权限错误和超时明确记失败，不当作不存在。
5. **下次会话与重试。** 不自动执行旧清理任务，下一次正常退出先按最新引用重新计算。任何条目重新使用同一哈希的素材（包括新 asset ID 或已登记公开 URL）都会取消整组清理；已有删除结果保留，需要发布时从本地补传所选图床中缺少的对象，不重新上传其他已停用图床。撤销或重新引用不依赖本次网络可用。

**完成条件：**该哈希组无引用、全部已登记远程目标删除完成、本地文件删除完成，才记为整组清理完成。S3 结果以对象接口为准，CDN 缓存是否即时失效不参与判断。MVP 使用普通对象删除；启用版本控制的桶可能保留历史版本，由桶自身策略管理，不增加版本扫描或永久擦除流程。[S3 DeleteObject 语义](https://docs.aws.amazon.com/AmazonS3/latest/API/API_DeleteObject.html)

通过上述退出条件后，也可移除 assets/ 内符合本应用哈希命名、没有任何 assets 记录的遗留文件；已有记录的文件必须遵循上述远程优先顺序。此检查仅覆盖应用素材目录，不扫描外部目录或远程桶来猜测孤立对象。

保留历史与软删除内容是真实引用；只从当前正文移除图片不代表立即删除其所有副本。强制结束进程只会推迟清理；恢复触发的重启跳过清理。数据库备份不阻止图片删除，也不能找回两端已删除的图片。外部页面直接使用的 S3 URL 会随对应对象删除而失效，公众号发布仍以保存草稿后的转存结果验收。

## 7. 公众号文章导入

首版从资料库导入公开 mp.weixin.qq.com 文章链接，保存为 reference。用户可从资料创建文章草稿并保留来源关联。Rust 导入服务使用 scraper 提取正文和来源信息，使用 Ammonia 净化，再由 htmd 转为 Markdown。微信原图下载限定已知的 HTTPS 图片域名。

**仅持久化清洗后的 Markdown、来源元数据和已下载的图片。** HTML 在转换后丢弃，**不生成原网页快照、不自动保留导入前版本**。sources 表只包含原文 URL、公众号名、作者、发布时间、导入时间等可追溯信息。

状态为 queued / running / completed / partial / needs_attention / failed，记录简洁错误信息。任务完成结果关联同一个 entry_id，重试不重复创建条目。规范化 source_url 由业务服务和数据库唯一约束完成导入去重；从资料创建文章只复用来源关系，不重复登记导入来源。

图片部分下载失败时，正文保留稳定 asset:// 占位，素材记录暂不含文件信息；jobs 记录 asset_id、原图片 URL 和目标条目。补图只填写该素材内容，不覆盖用户修改后的正文；该素材已无任何正文、封面或保留历史引用时跳过，仍被其他内容复用则继续补图。下载后按哈希复用文件和远程位置，保留正文中的稳定 asset ID；补图回调不直接清理素材，退出时统一按哈希组处理。重启后失败导入由用户按需重试，不重复抓取并覆盖现有正文。已存在链接打开已有条目；首版失败重试只补失败部分，不增加整篇覆盖或重新导入副本的功能。

安全边界：公开页面访问；限制 URL 协议、内网地址、重定向及下载大小；不执行原页面脚本；HTML 净化后进入 Markdown；遇平台验证时提示人工处理。原文来源保留在元数据中以便引用与二次创作。

## 8. S3 数据库备份与恢复

### 8.1 备份范围与策略

**每次仅生成并上传一个 SQLite 数据库快照文件**。不上传 assets/ 图片、附件、原始页面，也不建立完整工作区归档、资源 manifest 或多对象增量备份体系。

- 通过 [SQLite Online Backup API](https://www.sqlite.org/backup.html) 从独立连接读取活跃库，生成包含已提交 WAL 写入的单文件快照。
- 对生成的快照执行 SQLite integrity_check 和 foreign_key_check，然后上传到 S3 指定的数据库备份桶或前缀。
- 使用 `PRAGMA user_version` 选择正式迁移，比较表、索引和触发器结构。支持在 staging 迁移的旧版本，未知版本或结构不一致的快照会被拒绝。
- 快照对象名包含时间戳与唯一标识。默认保留最近 **5 个成功的数据库备份文件**；新备份上传成功后才清理更早文件。
- 对象位于配置前缀下的 `wechat-creator-workbench/<workspace_id>/backups/`，保留策略只作用于选定工作区且符合本应用命名格式的备份，不清理共享桶的其他文件。新设备配置 S3 后列出可选工作区备份目录，选定后恢复数据库中的原 workspace_id。
- S3 列举对象作为备份列表来源，不依赖已恢复数据库里的旧备份记录。
- 密钥不以明文放在数据库；备份数据库只包含非敏感的存储配置和安全存储凭据引用。

### 8.2 恢复步骤

**采用重启恢复，替换发生在编辑器、MCP 和任务服务启动前。** 不设计运行中热切换、多代数据库或版本 epoch。

1. 下载到 staging，检查 integrity_check、foreign_key_check 与 schema 兼容性；受支持的旧 schema 在临时副本上迁移并验证基本查询，失败不触碰当前库。
2. 用户确认恢复后停止新写入与任务，保存待提交正文；有失败先处理，不静默丢弃。停止并等待在途任务，写入一次待恢复标记，正常关闭全部数据库连接后重启。此次重启不执行图片清理。
3. 下次启动先处理待恢复标记：确认旧库通过 SQLite 正常关闭，完成 WAL 收尾；将当前库保留为一份回滚副本，再用同目录已验证的恢复文件替换。旧 WAL 不与新主文件混用，不直接删 WAL 代替关闭连接。
4. 新库打开且基本查询通过后移除待恢复标记和临时回滚副本，再启动编辑器与服务。替换失败回到旧库；若退出中断导致待恢复标记仍在，下次启动先完成或撤回这一次替换，不创建空库继续运行。仅保留这一份临时回滚副本，不增加通用恢复框架。
5. 重建前端状态，不恢复旧编辑缓冲或 AI 候选。恢复库中的未完成任务统一停止；导入和上传可由用户重新触发，AI 不自动重发，旧素材清理任务丢弃并在下次正常退出按新库引用重算。MCP 旧连接结束，重新连接后要求客户端重新读取正文与版本再写入。

**恢复范围限于数据库**：文章正文、分类、标签、少量历史、图床对象映射等可以恢复；本地图片无法随数据库自动恢复。已上传到图床且地址仍有效的图片可从远程加载，未上传的图片在新设备上可能缺失。

首版实现手动备份、备份列表和手动恢复，定时备份可后续增加。

## 9. HTTP MCP 与内置 AI

### 9.1 MCP

- 传输：标准 MCP Streamable HTTP，本地默认绑定 127.0.0.1，建议路径 /mcp，端口可配置。
- 使用 [rmcp 3.10.0](https://crates.io/crates/rmcp/3.10.0) 接入 Axum。SDK 负责初始化、协商与传输，支持 `2025-03-26`、`2025-06-18`、`2025-11-25` 和 `2026-07-28`。
- 生命周期：桌面启动后按设置启用；默认关闭外部写权限。
- 安全：令牌保存在系统凭据库，外部工具仅通过 Bearer 令牌连接。校验回环 Host，拒绝浏览器 Origin。请求体上限 1 MiB，每分钟最多 120 次已鉴权请求，操作日志只记录工具名和结果码。
- 统一服务：Tauri IPC 与 MCP 共用 EntryService、AssetService、ImportService，禁止 MCP 绕过业务层直接写 SQLite。
- 远程 Agent 不能默认访问本机 HTTP 服务；MVP 仅承诺本机 Agent 连接。

MVP 工具：

| 工具 | 主要输入 | 行为 |
| --- | --- | --- |
| list_entries | kind/status/category/pagination | 内容列表 |
| search_entries | query/filter | 文章/灵感/资料检索 |
| get_entry | id | 正文、元数据、版本 |
| create_entry | kind/title/content_md/category/tags | 新建草稿或资料 |
| update_entry | id/expected_version/patch | 乐观锁修改 |
| list_categories | parent_id | 分类树 |
| list_tags | query | 标签检索 |
| import_wechat_article | url | 创建导入任务 |
| get_job_status | job_id | 查询进度与结果 |

删除、批量覆写、远程公网访问在后续权限模型稳定后扩展。MCP 可以返回纯 Markdown 和素材元信息；富文本 HTML 生成先由前端排版模块完成，避免 Rust 端再造第二套解析器。

### 9.2 AI

首版支持用户自配兼容 OpenAI 风格的模型接口，集中由 Rust 侧发出请求，支持超时、取消、失败重试与用量记录；不同供应商通过接口适配。

场景：普通聊天、文章摘要、公众号标题候选和选区改写。普通聊天可引用选区、当前章节或显式选择的全文，OpenAI 风格接口支持流式回复；会话、消息和改写提案存于 SQLite。改写先在侧栏展示差异，用户确认后才修改正文。选区改写使用编辑器撤销，不创建关键版本。会话、上下文和提案的具体契约见 [AI 写作助手技术方案](./ai-writing-assistant-technical-design.md)。

修改提案绑定第 5.2 节的文章、编辑会话、修订与原范围；结果应用通过编辑器事务完成，再走普通自动保存，不由 AIService 直接覆盖数据库正文。正文已变化或原编辑会话结束时，候选仍可查看和复制。整篇覆盖的关键历史规则保留，本阶段不开放整篇重写。

用户的个人密钥不得直接进入模型提示词、应用日志、S3 备份或 Markdown 导出。外部资料/文章内容作为数据，不能解释为应用级指令。

## 11. 非功能要求与风险控制

1. **数据可靠性**：5 万字中文文章稳定编辑；已成功提交的 SQLite 正文在异常退出后仍完整；不因普通保存生成大量历史快照。
2. **离线体验**：不配置 S3/AI 时可写作、粘贴本地图片、预览和导出。公众号带图发布需根据图床情况走对应模式。
3. **基本安全**：所有内容入口的渲染输出净化、受控图片 URL、Tauri 插件与自定义 IPC 权限、系统凭据存储、MCP 本地认证与 Origin 校验；仅在真实边界校验。
4. **性能**：公式和流程图渲染节流缓存，上传/抓取/AI 使用后台任务，不阻塞打字；保存请求按文章串行，图片清理只在正常退出时执行。
5. **任务重启**：复用轻量 jobs。普通重启后上传和导入标记可重试，由用户触发；AI 不自动重发，素材清理留到正常退出时重查引用；数据库恢复按第 8.2 节清除旧任务影响。使用确定性对象 key 减少重复上传，不引入分布式租约。
6. **跨平台**：Windows 11 与 macOS 的中文输入法、图文剪贴板和公众号兼容性测试在最后的 P7 执行。
7. **开源许可与分发**：GPL-3.0、Plainly/主题来源和许可证清单；首发主题包只采用已核实授权的主题；Windows/macOS 签名与安装作为发布任务。
8. **备份范围声明**：S3 数据库快照仅覆盖 SQLite 内容，不保证本地图片在其他设备上恢复。

## 12. 最终验收基线

以下 A～H 是最终交付标准，不表示开发顺序或前置验证关卡。功能按第 1.5 节实现，P6 完成模块回归、黄金样例和候选构建，P7 完成端到端及真实服务验收；尚未执行的项目保持待验收。

- A：Plainly 排版核心和主题可独立运行，黄金渲染样例通过；复制等待本次输入渲染完成，净化覆盖编辑器、导入与 MCP 内容。
- B：SQLite 管理灵感、资料、文章、分类、标签；每篇文章保存串行且不覆盖新输入，普通自动保存不生成历史快照，关键版本最多 3 条；中文短词和过滤检索可用。
- C：本地图片粘贴可离线预览，异步插图不串文章；S3 图床单独上传；删除后撤销、取消退出均保留图片。正常退出按内容哈希组清理，仅全部已登记远程目标与本地文件均完成才记成功；部分失败保留未完成项，重新引用取消整组清理。完整场景见实施计划第 10.3 节。
- D：公众号文章只持久化清洗 Markdown、来源及资源重试信息，不产生原网页快照；补图不覆盖编辑后的正文，不重复创建条目。
- E：真实公众号后台保存和重新打开验证富文本与图片复制，无图床时可辅助逐图发布；HTML 与 Markdown 导出包包含独立素材，可离线打开。
- F：S3 完整提供数据库备份列表、单文件快照、重启恢复和工作区内 5 份保留策略；恢复前后不续写旧编辑缓冲、不重放旧任务，图片不属于数据库备份。
- G：HTTP MCP 完整支持核心内容检索/读写/导入，验证权限和版本冲突；AI 总结和改写可用，改写只应用于发起时仍有效的文档修订与范围。
- H：Windows/macOS 安装包、开源许可和基础使用文档齐全。

详细工作包、依赖、测试数据、可执行验收见 [implementation-plan.md](./implementation-plan.md)。
