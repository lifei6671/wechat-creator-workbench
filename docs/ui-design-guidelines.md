# 微信创作工作台 · 桌面界面与交互设计规范

> 版本：1.0  
> 适用：wechat-creator-workbench 的 Windows 11 / macOS 桌面界面  
> 技术基线：Tauri 2 + React + TypeScript + Radix UI Themes + CodeMirror 6  
> 产品架构：[MVP 技术方案](./mvp-technical-design.md) · 研发节奏：[实施计划](./implementation-plan.md)

## 1. 设计目标

本应用面向微信公众号创作者，主要任务是**快速收集灵感、整理参考资料、持续写作、排版并复制到公众号后台**。

交互方向：借鉴 Obsidian / VS Code 的信息密度、导航效率和桌面操作习惯；借鉴专注写作工具的低干扰编辑体验。主要界面是连续工作区，不是网站后台、卡片看板或仪表盘。

默认使用**紧凑工作台模式**；提供一键进入**专注写作模式**。这是同一套工作区的两种布局状态，不是两套独立 UI。

设计优先级：
1. 文章正文和公众号预览占据主要屏幕面积。
2. 灵感、资料、文章在相同导航范式下可快速切换和检索。
3. 编辑、保存、图片插入与发布动作始终明确；键盘和鼠标同等可用。
4. 桌面窗口、菜单、快捷键、拖放、剪贴板符合操作系统使用习惯。
5. Radix UI Themes 提供视觉基础，产品布局与操作组件形成自己的统一语言。

## 2. 组件选型与职责

| 技术 | 使用范围 | 约束 |
| --- | --- | --- |
| Radix UI Themes | 按钮、输入框、选择器、弹窗、菜单、提示、设置页表单 | 优先利用官方 props / 主题令牌，不大面积覆盖组件内部选择器 |
| Radix UI Primitives（按需） | Themes 难以覆盖的无障碍交互基础 | 同类控件优先选一种实现，避免叠加多个组件系统 |
| Lucide React | 统一线性图标 | 常规 16px、辅助 14px、空状态 24px，不混用多套图标风格 |
| react-resizable-panels 4.x | 工作区侧栏、编辑与预览的可调分栏 | 使用 Group / Panel / Separator API；布局尺寸持久化到界面设置 |
| CodeMirror 6 | Markdown 编辑、光标、选区、快捷键、撤销 | 编辑器主题与主界面协调，但不受通用表单字体规则影响 |
| Plainly 抽离模块 | 公众号排版、主题、代码块与富文本输出 | 公众号预览使用独立样式作用域，不继承工作台的组件样式 |
| 自定义 React 组件 | 活动栏、文章树、标签栏、状态栏、命令面板外壳、预览容器 | 只抽象至少在多个场景复用的逻辑，不为了设计体系建立庞大组件库 |
| Tauri 2 | 原生窗口、文件对话框、剪贴板、系统主题、菜单 | 原生能力由专门适配层调用，组件不直接散落系统 API |

**明确不采用**：基于大面积 Card 的后台仪表盘布局、多个彼此不兼容的主题系统、与工作流无关的视觉动画、为外观统一而重写可用的 Radix 基础控件。

Radix UI Themes 本身提供完整视觉样式；主工作区的导航、分栏、标签页与状态栏以项目 CSS 和设计变量实现，不强行使用 Radix Card 拼装。

## 3. 工作区信息架构

### 3.1 页面结构

~~~text
┌────────────────────────── 原生窗口标题栏 ───────────────────────────┐
│ 活动栏 │ 资源导航区  │       编辑器标签栏 / 当前文章标题            │
│  48px  │ 220–280px   ├──────────────────────┬─────────────────────┤
│        │             │ Markdown 源码编辑器 │ 公众号实时预览       │
│ 收集箱 │ 二级分类树  │                      │ 主题切换 / 手机宽度  │
│ 资料库 │ 标签/筛选   │                      │                     │
│ 文章库 │ 文章列表    │                      │                     │
│ 搜索   │             │                      │                     │
│ 素材   │             │                      │                     │
│ 设置   │             │                      │                     │
│        │             ├──────────────────────┴─────────────────────┤
│        │             │ 保存状态 · 字数 · 图片任务 · 当前主题          │
└────────┴─────────────┴──────────────────────────────────────────────┘
~~~

说明：右侧「文章属性 / 关联资料 / AI 助手」是按需展开的工具面板，默认不占据编辑器宽度。公众号预览是主工作区的可调面板，而非浮在内容上的固定手机模型。

### 3.2 推荐尺寸（CSS 像素，作为初始实现令牌）

| 区域 | 默认尺寸 | 行为 |
| --- | --- | --- |
| 窗口 | 1360 × 840 | 最小尺寸建议 1000 × 640；支持最大化及窗口记忆 |
| 活动栏 | 48px 宽 | 图标纵向排列，可折叠导航区 |
| 资源导航区 | 248px 宽 | 192–320px 范围可拖动；支持隐藏 |
| 顶部标签栏 | 36px 高 | 横向标签、未保存标识、标签关闭 |
| 工作区小工具栏 | 36–40px 高 | 仅放置编辑/预览切换、主题、复制等高频动作 |
| 编辑区与预览区 | 默认按剩余宽度 55:45 | 分割条可拖动；保存最后一次分栏比例 |
| 文章属性 / AI 面板 | 300–360px 宽 | 默认隐藏，展开时优先覆盖或压缩预览而非正文 |
| 底部状态栏 | 24px 高 | 轻量文字状态，不放主要操作大按钮 |

窗口宽度小于 1200px 时，首次打开默认显示单主编辑区，预览通过工具栏切换；用户主动启用双栏后尊重其选择。窗口过窄时优先折叠资源导航区和辅助面板，不能挤压编辑器到不可写状态。

### 3.3 三种编辑视图

- **双栏**（大窗口默认）：左侧 Markdown 源码，右侧公众号主题预览。
- **纯编辑**：编辑区居中，正文最佳阅读宽度约 720–840px；不因为窗口很宽而使文字行长无限增长。
- **纯预览**：以公众号实际呈现宽度展示主题内容，外围保留简洁的工具栏。

**专注写作**：暂时折叠活动栏、资源导航、属性/AI 面板，保留必要的返回入口与保存状态；退出专注后恢复原分栏宽度。不要覆盖原来的布局偏好。

## 4. 视觉系统

### 4.1 Radix 主题起点

- Theme 外观跟随系统浅色/深色；用户可以在设置中覆盖为浅色或深色。
- accentColor：indigo（靛蓝）；grayColor：slate（冷灰）；radius：small；scaling：95%；panelBackground：solid。
- 默认采用中性冷灰底色，强调色只用于选中、聚焦、主要动作及交互反馈；大面积编辑区域保持低干扰。
- 编辑器主题与公众号文章主题分别配置：切换公众号主题**不改变**应用窗口底色或 Markdown 编辑器底色。
- 所有工作区颜色使用项目语义变量映射 Radix 令牌，避免在各组件中直接写死颜色值。

~~~tsx
import { Theme } from "@radix-ui/themes";

<Theme
  appearance={resolvedAppearance} // 映射 Tauri 系统主题或用户选择，值为 light/dark
  accentColor="indigo"
  grayColor="slate"
  panelBackground="solid"
  radius="small"
  scaling="95%"
>
  <DesktopWorkspace />
</Theme>;
~~~

Radix 的 Theme 支持 appearance、accentColor、grayColor、panelBackground、radius、scaling 等属性；具体支持值见官方文档。这里的 95% 是初始密度选择，不代表应强制缩小正文编辑字体。

### 4.2 语义颜色变量

工作区定义语义变量，引用 Radix 颜色令牌：

~~~css
.workspace-shell {
  --app-bg: var(--gray-1);
  --sidebar-bg: var(--gray-2);
  --panel-bg: var(--gray-1);
  --panel-hover: var(--gray-3);
  --panel-selected: var(--accent-3);
  --divider-color: var(--gray-5);
  --text-main: var(--gray-12);
  --text-muted: var(--gray-10);
  --focus-color: var(--accent-9);
}
~~~

规则：背景层级最多 3 级（窗口/侧栏/编辑区）；区域主要靠分割线、轻微背景差与内容对齐区分，不依赖阴影和大卡片。Light/Dark 两种模式均需要检查对比度。

### 4.3 字体、间距与图标

| 元素 | 默认建议 |
| --- | --- |
| 导航/列表正文 | 13–14px，行高约 1.4 |
| 工具栏/状态栏 | 12–13px |
| 编辑器正文 | 15–16px，行高 1.65–1.8，可调 |
| 设置页标题 | 16–18px，不使用营销式大标题 |
| 菜单项高度 | 30–32px |
| 文章列表行高 | 32–36px |
| 常规按钮高度 | 28–32px |
| 图标 | 16px 为主，控制区点击范围不小于约 30px |
| 布局间距 | 4 / 8 / 12 / 16 / 24px 五档 |
| 边框 | 1px，使用主题分割线颜色 |
| 常规圆角 | 4–6px；弹窗可适当增大 |
| 动画 | 120–180ms，优先透明度与位移的小幅变化 |

这些数值是设计起点，不是测试结论。Windows/macOS 字体渲染差异与用户缩放可能要求微调；编辑器正文的可读性优先于工具栏密度。

不要用纯黑背景配纯白正文作为默认深色主题；不要通过降低到 11px 甚至更小来制造信息密度。中英文混排需要检查字重、标点和字号。

## 5. 组件规范与交互规则

### 5.1 侧栏与文章列表

- 活动栏采用图标 + 工具提示；选中项有可辨识的竖线或底色，并带可访问名称。
- 文章库显示二级分类树；展开/折叠状态记忆到界面设置。标签为筛选条件，不生成第三层目录。
- 文章列表优先标题、状态、小号修改时间；选中行为打开标签页，双击不应触发第二份副本。
- 右键菜单根据对象提供新建、重命名、移动分类、复制链接、归档等当前已实现动作。
- 拖动排序仅用于有明确排序业务意义的位置；不为每个列表项附加拖拽交互。
- 每种列表设置统一的 hover、selected、focus-visible、disabled 状态，选中不能只依赖颜色变化。

### 5.2 标签页与编辑器

- 每篇打开的文章对应一个标签（使用稳定 entryId）；重复打开聚焦已有标签。
- 标签栏支持鼠标切换、关闭、中键关闭（Windows 平台按常见习惯）、键盘导航；关闭前先处理正在进行的保存。
- 未保存指示仅在存在本地未提交修改时显示；状态栏区分「保存中」「已保存」「保存失败」。
- 图片粘贴与异步插入绑定当前文章和插入位置，后续切换标签不应插错文章；与现有技术方案的异步修订约束保持一致。
- 预览随 Markdown 变化更新，复杂公式/流程图适度节流；预览滚动与编辑滚动的同步可由用户关闭。
- 编辑器布局、字号、换行、制表符和主题不直接继承 Radix 的表单控件排版设置。

### 5.3 内容类型：灵感 / 资料 / 文章

- **收集箱**：一次操作可以开始记录，允许没有标题；支持快速粘贴文字、链接与截图。默认聚焦内容输入。
- **资料库**：优先显示来源、作者、采集时间、摘要和清洗正文；导入状态使用行内反馈或轻量任务提示。
- **文章库**：优先显示写作状态、分类、标签、摘要、封面、公众号主题和发布入口。
- 同一内容编辑区复用底层编辑器，属性面板随 kind 改变，避免为三类内容实现三套编辑器。

### 5.4 命令面板和快捷键

命令面板负责快速打开文章、执行「新建文章」「记录灵感」「导入公众号链接」「切换预览」「复制公众号格式」等动作。支持中文关键词、键盘上下选择、回车执行、Esc 关闭。

| 操作 | Windows | macOS |
| --- | --- | --- |
| 打开命令面板 | Ctrl + K | Command + K |
| 新建文章 | Ctrl + N | Command + N |
| 新建灵感 | Ctrl + Shift + N | Command + Shift + N |
| 手动立即保存 | Ctrl + S | Command + S |
| 打开全文搜索 | Ctrl + Shift + F | Command + Shift + F |
| 编辑 / 预览切换 | 在设置中查看并可自定义 | 在设置中查看并可自定义 |

实现前检查系统快捷键、Tauri 菜单和 CodeMirror 默认绑定之间的冲突。禁止因为快捷键截获导致中文输入法组合输入中断；输入法激活时不要运行全局命令。

### 5.5 反馈与错误

- 保存、复制、导入、S3 上传与 MCP 启用状态应通过靠近操作位置的反馈展示；成功状态简洁，失败状态提供下一步操作。
- 复制公众号富文本成功表示**剪贴板已写入**，不是公众号已持久保存；发布结果由用户确认。
- 无 S3 图床时保留写作与本地预览，公众号带图发布使用「按正文顺序逐张处理图片」流程。
- 一般后台任务使用进度区或状态栏；不可逆操作才使用确认对话框。
- 空状态提供直接可执行的主操作，如「新建文章」「记录灵感」「粘贴公众号链接」，避免装饰性信息卡和空泛文案。

## 6. 桌面系统适配

### 6.1 窗口

首版优先保留 Windows/macOS 原生窗口装饰与系统窗口控制，应用顶部工作区标题栏位于内容区。不要只为视觉统一就关闭系统装饰并重建完整标题栏。

macOS 的透明标题栏或 overlay 可在后续视觉优化中评估，必须处理交通灯控制区、窗口拖动、全屏和内容安全区。Tauri 官方文档说明自定义标题栏会带来系统行为差异，窗口控制权限也需要显式配置。

### 6.2 原生行为

- 支持系统浅色/深色变化，保留用户显式外观选择。
- 支持系统文件选择、Markdown/HTML 导出目录、剪贴板图片、拖拽文件和外部 URL。
- 可点击区域、右键菜单、滚轮、触控板滚动遵循系统习惯。
- 跨平台菜单文本与快捷键提示区分 Ctrl / Command；错误提示和按钮文案默认简体中文。
- 根据 Tauri 当前配置安排窗口最大化、最小化、关闭和安全退出，不让网页式导航替代原生窗口能力。

## 7. 公众号预览边界

公众号预览不是普通业务卡片，是**独立内容呈现容器**：

1. 由 Plainly 抽离的渲染器产出主题化 HTML，导出与预览尽量共享同一渲染路径。
2. Radix Theme、工作区全局 CSS 不得污染公众号文章内部的字体、标题、段距、图片样式。
3. 公众号主题切换只影响文章预览与导出结果，不影响应用外壳、侧栏和 CodeMirror。
4. 预览宽度以手机阅读尺度为参考（建议约 375–430px 的内容容器，可调），不模拟没有功能意义的手机外框。
5. 图片在编辑预览时使用本地资产解析；复制公众号前才解析为已配置图床公开 URL 或提供图片辅助发布。
6. 所有 Markdown 入口（编辑器、导入、MCP）经过既有技术方案定义的 HTML 净化边界。
7. 正文/预览分栏间的滚动同步以标题锚点或可靠位置映射实现，不能为了同步引入输入卡顿。

## 8. 可用性与无障碍

- 所有主要操作有键盘路径；菜单、对话框、弹出层必须支持焦点进入、Tab 导航、Esc 关闭及合理的焦点恢复。
- 分栏拖动除鼠标外须支持键盘操作；使用 react-resizable-panels v4 的 Separator，检查焦点样式和键盘调整。
- 重要状态除颜色外还要提供文本或图标；悬浮说明不能是唯一操作入口。
- 浅色与深色模式中，正文、辅助文本、分割线、焦点轮廓具有足够对比度；可用 WCAG 2.2 AA 作为检查基准。
- 尊重 prefers-reduced-motion；降低动画；缩放到 125%/150% 时能正常输入和导航。
- 长文编辑和预览时不频繁抢夺焦点或滚动位置；弹窗关闭后回到触发控件或原编辑区。

## 9. 组件实现约定

建议的最小结构，不提前建立独立设计系统仓库：

~~~text
apps/desktop/src/
  app/
    DesktopShell.tsx
    theme.ts
  components/
    workspace/
      ActivityBar.tsx
      ExplorerPane.tsx
      DocumentTabs.tsx
      WorkspacePanels.tsx
      StatusBar.tsx
    common/
      CommandPalette.tsx
  features/
    inbox/
    references/
    articles/
    editor/
    publishing/
  styles/
    tokens.css
    desktop-shell.css
~~~

- Radix Theme 在应用根部初始化；全局视觉变量在 tokens.css 集中定义。
- 工作区自定义组件使用语义类名，避免依赖 Radix 内部 DOM 层级写大量穿透 CSS。
- 分栏、侧栏可见性和编辑器显示模式属于界面偏好，不属于文章实体内容；可以保存在 app_settings 或已存在的本地界面设置服务。
- 不为一次性的页面样式建立独立抽象；一套按钮、一套弹窗、一套通知交互即可。
- 根据当前仓库技术方案，将自动保存、图片清理、S3、MCP 和 AI 的真实业务逻辑留在既有服务层；界面只承担发起操作与结果表达。

## 10. 开发验收清单

在现有实施计划中同步落实，不新增前置 UI 原型关卡：

| 阶段 | 应落地的 UI 范围 | 检查重点 |
| --- | --- | --- |
| P0 工程底座 | Radix Theme、基本工作区外壳、编辑器与预览区、基础窗口 | 可运行、布局连续、主编辑区不被卡片挤占 |
| P1 内容管理 | 活动栏、分类与文章列表、标签栏、自动保存反馈、三种内容入口 | 鼠标键盘可快速切换内容，写作流畅 |
| P2/P3 素材与公众号 | 图片粘贴状态、主题切换、公众号预览、复制与导入反馈 | 预览样式隔离，图片与内容位置对应 |
| P4/P5 MCP、AI、备份 | 设置表单、模型配置、任务/错误提示、只读及写入权限表达 | 错误可理解，后台功能不打断编辑 |
| P6/P7 回归与发布 | 明暗主题、缩放、Windows/macOS、键盘无障碍与兼容性 | 实际截图和操作验收，真实公众号粘贴测试 |

逐项人工检查：
1. 1360×840 和 1000×640 下，创建文章、编辑、预览、复制无需跨多个页面跳转。
2. 资源导航、编辑器、公众号预览能折叠与拖动，关闭再打开保留布局。
3. 文章列表数百条时可顺畅滚动；打开多个标签不出现重复文章实例。
4. 全部常用操作存在快捷键或明确菜单入口；中文输入法正常输入。
5. 工作区浅色、深色和 125%/150% 缩放下可读；公众号主题不污染应用外观。
6. 网络断开时本地写作和图片预览可用；相关功能提示准确。
7. 保存与复制成功反馈对应真实动作，用户能区分本地保存、S3 上传与公众号后台保存。
