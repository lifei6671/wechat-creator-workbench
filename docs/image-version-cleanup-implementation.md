# 图片旧版本自动清理

图片编辑成品采用后台自动回收，不需要选择候选或确认删除。素材库的“旧版本图片”窗口用于查看状态、保留和恢复。

## 保留与回收

- 保留原图、当前内容及工程引用、递归输入、最近 5 个成品、创建不足 30 天的版本，以及发布、外发、备份和编辑恢复仍需要的图片。
- 历史图床记录及用途不明的位置继续保留；早期未隔离命名空间的私有裸摘要对象也保守保留。新上传成功不等于已经外发；完整登记的新托管成品才有资格进入自动清理。
- 闲置版本先等待 7 天，执行前重新核对引用和对象身份。字节备份通过大小及 SHA-256 回读校验后，才删除原位置。
- 回收副本至少保留 30 天，后续后台轮次处理到期副本。恢复生成新物理位置，旧删除请求无法删除恢复后的新位置。
- 本地后台每 10 分钟检查；云端生命周期随同步后的检查推进。设备离线、尚有未确认操作或检查未完成时，远端清理等待，不自动撤销设备。

同一内容的逻辑版本合并判断引用；公开图床实际压缩字节单独记录摘要，不能用原图摘要校验压缩对象。失败、内容变化、凭据缺失或提供者拒绝条件删除时，保留任务及错误，不扩大删除范围。

## 存储与同步

| 范围 | 实现 |
| --- | --- |
| 本地原图字节 | `0039_image_version_cleanup.sql`、`assets/version_cleanup`；在工作区锁内完成最终核对和删除，备份使用临时文件、同步写盘和校验 |
| 公开 S3 图床 | 新对象登记 copy、generation、真实存储 scope、压缩摘要和对象归属 metadata；删除使用指定对象版本或 ETag 条件，删除前再次读取指定身份核验 |
| 同步私有存储 | `0010_image_version_gc.sql`、`image-gc-store.ts`；逻辑摘要映射到带实例、世代及 generation 的物理 key，R2 与 Node 本地文件适配均支持 |
| 设备协调 | 协议 3 的可选 `imageVersionGc: 1` 能力；完整扫描、持久使用屏障及精确 round/revision/cursor 回执，所有有效设备确认后才授权 |
| 并发使用 | 正常同步事务中的引用 fence 拒绝重新使用删除中的对象；离线变更保留为待同步内容，恢复成功后再提交；实际外发先取得保护确认 |
| 字节恢复 | 本地副本或已校验云端回收副本恢复到新 generation；提供合法同摘要字节仍可恢复，不把曾到期的摘要列入黑名单 |

剪贴板、Markdown/HTML 导出在实际交付前保护使用的图片；旧托管地址需要恢复时，输出同内容的新地址。后台上传和缩略图读取不登记用户编辑会话使用，显式读图才登记。

原始场景、成品、素材和同步回执保留。已应用回执只证明历史提交成立，不能证明字节仍可下载。首次同步可登记已到期的闲置衍生历史元数据，不伪造可读 blob；实际内容仍需通过引用和字节验证。

## 备份与重建

迁移包包含当前用途需要的原图，以及仍存在的本地回收字节和图床实际压缩回收字节。远端已退休的状态不能覆盖本机尚未同步的实际引用；只允许闲置历史缺少已回收的字节。仍存在的闲置缓存也可打包。

未知备份保护阻止继续删除现有字节，不要求重新生成已经合法到期的闲置历史。实际引用的原图缺失时，导出会失败并保留原工作区。

恢复数据库后，历史公开位置重新进入保守保护；暂停重建先刷新云端生命周期，再检查当前工程需要的原图。数据库备份本身不等于图片字节备份。

## 服务升级与兼容

Cloudflare 部署须先将现有 D1 迁移至 `0010_image_version_gc.sql`，再部署匹配的服务端代码；保留原 D1、R2、实例、工作区及密钥。Node 服务沿用原持久化目录并应用迁移。不要配置桶级图片年龄清理规则。

所有未撤销设备均需支持并完成检查，远端删除才能推进。旧客户端不能确认该能力，因此会阻止回收。已发生回收后，重装或完整重建历史应使用新版客户端；不保证旧客户端能下载已退休字节。已采用托管物理位置的工作区不能直接回滚到不识别映射的旧服务端。

服务端尚未支持能力时，普通同步沿用保守保护，新公开上传继续保留；已有不可用历史需要新版服务端处理，不静默丢弃历史。对象锁、版本或条件请求的支持仍取决于 S3 提供者，隔离适配验收不能替代具体服务的验证。
