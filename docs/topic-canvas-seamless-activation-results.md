# 专题画布网页平滑激活验收

## 改造前诊断

使用隔离的 Windows 11 Release 工作区测试本机固定页和动态长页。固定卡片内容区为 294 × 214 CSS px。在 Windows 150% 显示比例、画布 100% 缩放下，截图为 441 × 321 px，重开前后的网页 `innerWidth` 和测试段落宽度相同。

- **静态替换。** 重新选中动态页时，新 PNG 直接替换旧图。实际桌面标记颜色一步切换，没有采到中间颜色。
- **原生交接。** `open` 用时约 60–71 ms，激活截图用时约 59–73 ms。截图命令返回后约 2–3 ms 就发送 `reveal`，期间没有图片过渡。卡片在普通点击时未触发画布聚焦。
- **页面重载。** 固定页的滚动位置从约 672 px 归零。页面导航到测试站的 `/long` 后，切到另一张卡片再回来会打开原始地址 `/fixed`。

## 实现与恢复边界

继续由单选状态控制一个原生 WebView2。旧图保留在卡片内，新 PNG 解码后从同一左上角以自然宽高比绘制。新图完成 150 ms 渐入，缓存提交并在主视图绘出一帧后，才抬起原生子窗口。减少动态效果时直接提交已解码的图。卡片选择、尺寸或导航变化使交接失效时，取消旧交接并释放临时对象 URL。

取消选中时先遮挡旧子视图，随后读取实际 URL 和滚动位置。位置仅保留在已打开专题的内存里，重激活时先恢复位置，再捕获交接图片。对有效内容出现前的空截图继续等待。页面变短或已绘制的加载骨架使目标位置不可达时，最终使用当前可达位置。页面仍会重建，登录状态、站点脚本的内存状态和实时数据可能变化。

## 验证方法

Windows 11 专业版 26200，WebView2 157.0.4341.46。用同一固定页和每次重载改变标记颜色的动态页，在 50%、100%、200%、300% 画布倍率下各重激活五次。实际系统显示比例为 150%。100% 条件采用应用进程 DPI 兼容模式，应用 DPI 为 96、WebView2 DPR 为 1，显示器仍保持 150%。

从点击事件到原生 `reveal` 返回统计 P50/P95。用 Windows 桌面采样比较旧截图和接管后原生画面中的标记边缘，并检查标记中心白帧及图片区外四个采样点。采样指标只代表所测区域和时刻。

## Windows Release 结果

两种 DPI 设置共完成 **80 轮**重激活，每组 5 轮。最大标记位移 **0.67 CSS px**，低于 2 CSS px 目标。全程 1,164 个标记中心采样中未见白帧，接管前后的越界采样为 0。动态页每轮采到 6–9 个颜色值，验证了原生接管前的渐变确实出现在桌面画面上。
