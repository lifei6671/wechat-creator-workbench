# 微信创作工作台实施计划与验收

> 配套架构：[MVP 技术方案](./mvp-technical-design.md)  
> 版本：1.3（核心功能优先，验证后置）
>
> 执行对象：Codex / 工程开发者  
> 范围：MVP 首个公开测试版；目标平台 Windows 11、macOS。  
> 工作方式：先完成核心功能，再集中回归，最后端到端验收；功能开发期间只做必要的针对性检查，每个工作包提交独立且可审查的变更。

## 0. 开工前的工程约束

- 本仓库是新项目，依赖 Plainly 的是**可复用能力**，不是 Plainly 的应用生命周期、旧数据模型和远程用户系统。
- 桌面界面遵循 [桌面界面与交互设计规范](./ui-design-guidelines.md)，主界面使用 Radix UI Themes + 自定义工作区组件，并保持公众号预览的样式隔离。
- 源码以 React + TypeScript + Tauri 2 + Rust + SQLite 构建；Markdown 只存 SQLite；图片本地保存、可独立上传 S3 图床。S3 数据备份只包含 SQLite 数据库文件。
- 复用 Plainly 前先锁定来源提交，并在 docs 中登记代码/主题的来源、版本、许可。保留 GPL-3.0 与第三方 NOTICE。
- 所有数据库写操作必须由 Rust 应用服务统一处理；MCP 与桌面界面使用同一业务规则。
- 修改数据库模型、内部图片 URI、备份文件格式、MCP 工具契约时，同步更新技术方案与迁移脚本、测试。
- 用户数据不默认上传；不配置 S3 或模型接口时可写作、收藏、编辑、搜索、Markdown 导出；无图床时公众号图片按辅助逐图发布流程处理。
- 交付时提供实际运行的测试与测试结果，不能把设计推断视为已验证的公众号兼容性。
- 禁止防御性编程：只覆盖当前正常业务流程和会实际遇到的失败，不为极低概率情况增加重复校验、兜底、通用恢复框架或复杂状态机；内部复用入口已确认的约束。
- 图片自动保存只更新引用，正常退出时按内容哈希组清理；该组本地文件和全部已登记 S3 目标均完成才算成功。取消退出保留撤销历史，取消清理只停止剩余删除并继续退出；数据库恢复触发的重启跳过清理。专项验收统一见第 10.3 节。
- P0～P5 优先交付实际功能，不设置独立验证原型、兼容性报告或完整测试样本集作为业务开发的前置关卡。开发中保留构建、类型检查及受影响行为的必要单元/组件测试；集中回归、黄金样例和性能验证放在 P6，端到端测试的搭建与执行、真实公众号/S3/MCP 客户端验收放在最后的 P7。
- 验证后置只调整开发流程。图床连接测试、备份完整性检查、导出前素材检查等产品功能仍随所属模块实现，不推迟到验收阶段。

## 1. 工作包依赖

~~~mermaid

  C["P0 工程底座"] --> L["P1 内容管理 / 编辑保存"]
  L --> A["P2 素材与 S3 图床"]
  A --> W["P3 Plainly 排版 / 导入发布"]
  L --> M["P4 MCP / AI"]
  L --> B["P5 SQLite 数据库备份恢复"]
  W --> R["P6 集中回归 / 发布构建"]
  M --> R
  B --> R
  R --> E["P7 最终端到端验收 / 发布"]
~~~

默认按 P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7 执行。图中表示功能依赖：P4、P5 的基础实现可在 P1 接口稳定后开始；P4 的导入工具最终接入 P3 ImportService，P5 的恢复流程接入 P2 素材任务和 P4 MCP/AI 的停止机制。所有核心功能及这些接口接入均在 P6 前完成，MCP 与 S3 数据库备份仍属于公开 Beta 必须交付能力。

各功能阶段的完成条件用于确认功能已接入、必要局部检查通过，不要求提前完成真实服务、跨平台或整条用户流程的验收。完整验收集中在 P7，不阻塞后续核心模块开发。

## 3. P1 SQLite 内容管理与 Obsidian 式桌面交互

### 3.1 Rust 领域模块

- [x] SQLite 初始化、迁移、WAL、foreign_keys、错误码、事务包装、数据库完整性检查。
- [x] entries 统一模型：idea/reference/article；标题、正文、状态、分类、标签、来源、版本。
- [x] CategoryService：两级分类、排序、同级重名校验、删除重归类。
- [x] TagService：创建、关联、规范化和过滤。
- [x] EntryService：创建、读取、更新、软删除、恢复、分页、筛选。
- [x] RevisionService：仅手动保存版本、AI 整篇覆盖前保留关键历史，每条目最多 3 份；自动保存不生成全文历史；乐观锁 expectedVersion。
- [x] SearchService：FTS5 trigram；不足 3 字符使用参数化 LIKE 回退，搜索输入按普通文本处理，覆盖字面通配字符和分类/标签联合过滤。
- [x] 初始化稳定 workspace_id；恢复备份时使用备份原有 ID，供 S3 图床与数据库备份划分命名空间。
- [x] IPC：只暴露稳定 DTO，不直接返回数据库行对象。
- [x] 内容关联：灵感/资料与文章的 entry_links。

### 3.2 前端

- [x] 目录、搜索与素材接入自绘标题栏，回收站与设置位于侧栏底部。
- [x] 三种内容共用两级目录树，支持自定义文件夹图标；标签作为全文搜索筛选项。
- [x] 自绘标题栏多标签页：打开/切换内容、未保存状态、离开前保存提醒；只保证数据库已成功提交的正文。
- [x] Milkdown 富文本编辑器：Markdown 持久化，快捷键、查找替换、选区操作、正文右键排版和插入。
- [x] 单栏编辑、双栏、公众号预览与只读阅读模式；分享菜单提供公众号格式复制及导出。
- [x] 自动保存防抖、切换保存和失败提示；冲突时停止覆盖、保留内存内容，允许复制当前稿、另存草稿或重新加载；MCP 返回 VERSION_CONFLICT。
- [x] 每篇文章最多一个在途保存请求，新输入合并待提交；响应关联本地修订号，不回填覆盖新输入。切换、失焦、正常退出共用保存队列，保存失败保留窗口供处理。
- [x] 退出准备阶段暂停新编辑和服务写入；保存失败或取消退出时恢复编辑与服务，保留缓冲和撤销历史，实际决定退出后才结束编辑会话。
- [x] 编辑器异步目标包含 entryId、本地修订号、范围和原文；切换标签保留对应编辑状态，关闭标签结束该编辑会话。图片位置使用编辑器已有映射，不自行实现范围合并算法。
- [x] 从灵感/资料创建文章草稿，保留来源关联。
- [x] 导出单篇 .md（此阶段可只含纯文本，带图导出由 P2 完成）。

**完成条件**：内容增删改查、分类/标签、编辑保存、检索和纯文本导出均已接入界面。用必要的服务/组件测试检查版本冲突、保存队列、关键历史和迁移，不在此阶段执行整套用户流程。批量搜索与长文性能在 P6 验证；关闭重开、中文输入法及连续编辑叠加切换/退出的端到端验收放在 P7。

## 4. P2 素材库、图片粘贴与 S3 图床

- [x] 建立 AssetService 与 AssetUrlResolver；支持稳定 asset:// 逻辑 URI。
- [x] 实现剪贴板图片粘贴、图片拖入、多文件处理，绑定发起时的文章和插入位置；后续输入使用编辑器位置映射，原文档关闭或目标被删除后不插入其他文章。
- [x] 校验图片文件头、尺寸与大小；按 SHA-256 去重，多个逻辑 asset ID 可共用一份哈希文件。远程位置按哈希和准确存储目标去重，清理任务也按哈希复用。
- [x] Rust 使用现有 Markdown 解析器权威生成 entry_assets，并随正文事务更新；前后端共用必要引用样例，覆盖内联图片、引用式图片、HTML img src、已登记图床 URL，排除普通代码和转义文本。封面独立维护，保留历史按同样规则提取引用；派生 source_key 在 P3 接入。
- [x] 实现图片预览加载及可见的失败占位；本地图片无需 S3 即可显示。
- [x] 建立 S3StorageProvider，支持 endpoint/region/bucket、上传/下载/删除、超时取消与错误归类；连接测试用应用创建的对象验证上传、读取和删除权限，清理遵循普通对象删除语义，不增加桶历史版本扫描。
- [x] 图床公开域名与备份私有桶分开配置；凭据用操作系统密钥存储。
- [x] 实现 upload jobs（queued/running/retrying/completed/failed）及任务状态 UI。
- [x] 上传请求发出前登记工作区专属前缀内的确定性 object key 和准确存储目标，失败/取消保留映射。变更存储目标使用新配置，仍有未删除对象映射的旧配置及凭据引用保留；外部来源 URL 不登记为应用拥有的对象。
- [x] 实现技术方案第 6.4 节退出流程：取消排队上传，结束在途素材任务；若仍有素材写任务或未正常结束的已发送上传，本次跳过整轮清理。其余情况在停止业务写入后一次计算引用，不增加按任务维护的素材保护表。
- [x] 按哈希合并全部正文、封面、最多 3 条历史、可恢复软删除内容的图片引用，以及派生 source_key 引用；组内任何引用都保留整组。已登记公开 URL 也参与引用判断，外部源站原图不删除。
- [x] 保留从素材库直接导入的哈希组。其余无引用组逐个删除尚未完成的已登记远程目标（含未确认上传成功的目标），记录每个目标结果；全部远程完成再删本地，本地完成才移除素材/位置记录并完成清理任务。取消该组待上传/补图项，不移除导入任务的其他结果；无文件占位只清理记录和对应补图项。
- [x] 每次退出一轮尝试，失败/取消保留未完成项，允许停止余下清理直接退出。再次引用任一同哈希素材取消整组任务，保留已发生的远程删除结果，需要发布时只补传所选图床中缺少的对象；下一次退出仍先重查引用。
- [x] 任务已结束且允许清理时，检查应用 assets/ 中无数据库记录的哈希文件；已有记录的文件遵循远程优先顺序，不扫描远程桶或外部目录回收孤立对象。
- [x] 完成带图片的 Markdown 压缩包导出：改写素材 URI 为相对路径，导出文章元信息与对应图片。
- [x] 素材缺失时提示；数据库恢复后可使用已有图床远程 URL 读取，纯本地图片不保证恢复。

**完成条件**：本地素材、S3 上传/删除、退出清理、任务状态和带图 Markdown 导出均已接入。用必要的领域/组件测试检查哈希去重、引用判断、异步目标及远程优先删除顺序；完整删除/撤销/S3 流程、断网重启和导出包阅读器检查统一在 P7 执行，不作为进入 P3 的关卡。图片生命周期以第 10.3 节 G01～G14 为最终验收标准。

## 6. P4 MCP 服务与 AI

### 6.1 MCP

### 10.2 建议质量门槛

- Rust 领域服务中所有关键状态转换有单元测试或集成测试。
- 文章、标签、分类、素材引用及版本号依赖数据库约束与事务；正文引用为权威数据，entry_assets 由保存过程重建。
- 用户确认已保存的正文在强制终止/重启后完整。
- 同一文章串行保存，异步结果不覆盖新输入或其他文章；素材物理清理不发生在可撤销的编辑会话内。
- 正常退出的素材清理以本地文件和全部应用管理的 S3 对象删除为完成条件；网络失败可追踪且保留本地文件，不靠吞掉错误或无限重试完成退出。
- 无 S3/AI 时完整完成本地写作；关闭网络不影响已保存素材预览。
- 公众号粘贴成功与否以真实保存草稿重开结果为准，不使用复制 API 返回值代替。
- 本文列出的实际失败场景具有清晰错误提示和可重试或人工处理入口；不为理论上的所有异常增加兜底和自动恢复。

### 10.3 图片生命周期专项验收

以下均为待实现后的最终验收项，完整流程统一在 P7 执行。开发时可对引用判断和删除顺序做必要局部测试，P6 集中回归这些模块；P7 再串联桌面操作，并在实际 S3 兼容服务上验证上传、读取、删除权限及对象接口结果，不能以模拟测试代替远程验收。默认以无版本控制的测试桶检查物理删除；桶自行保留的历史版本与 CDN 缓存不属于应用清理范围。

| 编号 | 操作场景 | 必须观察到的结果 |
| --- | --- | --- |
| G01 | 删除正文图片 → 自动保存 → 撤销，再重做并正常退出 | 编辑会话内两端始终保留；退出时按最终已提交引用决定清理，撤销不依赖网络 |
| G02 | 保存失败或取消退出 | 不开始任何物理删除，保留正文和撤销历史，恢复编辑与服务；关闭单个标签也不触发清理 |
| G03 | 同图跨文章、封面、关键历史、软删除条目或不同 asset ID 复用 | 任一引用存在就保留整个哈希组；最后引用消失后，在远程可用且任务已结束的退出中两端均删除，远程每个目标只处理一次 |
| G04 | 无引用图片有两个远程位置，其中一个删除失败 | 成功目标记已删除，失败目标保留，本地文件和素材记录保留；下次退出只尝试剩余目标，不误报整组完成 |
| G05 | G04 之后重新插入同一文件、新 asset ID 或已登记图床 URL | 取消同哈希组清理，离线可用本地图片；已删远程地址不冒充可用，发布时只补传所选图床缺少的对象 |
| G06 | 远程已全部删除，本地删除失败 | 保留本地失败状态及素材记录，下次无引用时只补本地删除，成功后才移除整组记录 |
| G07 | 上传排队或正在上传时退出 | 排队上传取消；发送前已有准确目标记录。存在未结束素材任务或已发送上传未正常结束时跳过本轮清理，不并发上传/删除同一对象；后续退出可以清理登记目标 |
| G08 | 清理进行到一半取消，或远程返回权限错误/超时 | 停止剩余清理并退出，不返回已失去部分素材的原撤销会话；保留逐目标结果。错误不当作不存在，不无限重试 |
| G09 | 用已登记 S3 URL 引用图片；另导入外部来源图片 | 已登记 URL 计入引用并保护对应组；外部来源图片只清理应用本地/图床副本，绝不向来源站点删除原图 |
| G10 | 公式/图表导出后改其他段落、换主题；导出新源码后撤销回旧源码；源片段只在历史中存在 | 以源片段 source_key 而非整篇正文指纹保留原图。源片段与图片直接引用全部消失后才在正常退出清理；导出文件自身的图片副本不受影响 |
| G11 | 部分导入形成无文件占位；取消插图留下未登记哈希文件 | 无引用占位连同对应补图项移除，不请求 S3；允许清理时只移除应用 assets/ 内无记录哈希文件，有记录且远程删除失败的本地文件不能被此步骤绕过删除 |
| G12 | 图床配置变更、删除权限不足 | 连接测试包含删除权限；旧对象仍使用原存储目标，尚有关联的旧配置不能直接删除；凭据不足明确失败并保留待处理目标 |
| G13 | 强制结束应用后重新打开 | 不要求强制退出完成清理；旧清理任务不自动执行，下一次正常退出先依据当前引用决定，新增引用不会被旧任务删除 |
| G14 | 恢复数据库触发重启、再恢复含已删除图片的旧快照 | 恢复前不清理图片，旧清理任务不重放；下次退出使用恢复库引用，已经两端删除的图片显示缺失，不宣称可由数据库恢复 |

- 初次实现数据表时同步落盘 SQL migration，并记录版本编号。
- 对 MCP 工具的输入、输出、错误码建立稳定协议文档和契约测试。
- 公众号复制行为发生兼容性变化时，更新测试矩阵及支持范围。
- Plainly 的第三方主题增加/升级时，同步维护许可来源和黄金渲染样本。
- 对 MVP 范围外能力单独建任务，不提前增加多端同步、公众号自动发布、知识图谱和插件市场等复杂度。
