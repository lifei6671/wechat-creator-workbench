# 微信创作工作台实施计划与验收

> 配套架构：[MVP 技术方案](./mvp-technical-design.md)  
> 版本：1.2（图片生命周期复核）
>
> 执行对象：Codex / 工程开发者  
> 范围：MVP 首个公开测试版；目标平台 Windows 11、macOS。  
> 工作方式：逐工作包实现、测试、验收；一个工作包完成后提交独立且可审查的变更。

## 0. 开工前的工程约束

- 本仓库是新项目，依赖 Plainly 的是**可复用能力**，不是 Plainly 的应用生命周期、旧数据模型和远程用户系统。
- 源码以 React + TypeScript + Tauri 2 + Rust + SQLite 构建；Markdown 只存 SQLite；图片本地保存、可独立上传 S3 图床。S3 数据备份只包含 SQLite 数据库文件。
- 复用 Plainly 前先锁定来源提交，并在 docs 中登记代码/主题的来源、版本、许可。保留 GPL-3.0 与第三方 NOTICE。
- 所有数据库写操作必须由 Rust 应用服务统一处理；MCP 与桌面界面使用同一业务规则。
- 修改数据库模型、内部图片 URI、备份文件格式、MCP 工具契约时，同步更新技术方案与迁移脚本、测试。
- 用户数据不默认上传；不配置 S3 或模型接口时可写作、收藏、编辑、搜索、Markdown 导出；无图床时公众号图片按辅助逐图发布流程处理。
- 交付时提供实际运行的测试与测试结果，不能把设计推断视为已验证的公众号兼容性。
- 禁止防御性编程：只覆盖当前正常业务流程和会实际遇到的失败，不为极低概率情况增加重复校验、兜底、通用恢复框架或复杂状态机；内部复用入口已确认的约束。
- 图片自动保存只更新引用，正常退出时按内容哈希组清理；该组本地文件和全部已登记 S3 目标均完成才算成功。取消退出保留撤销历史，取消清理只停止剩余删除并继续退出；数据库恢复触发的重启跳过清理。专项验收统一见第 10.3 节。

## 2. P0 公众号发布技术验证

**目的**：检验 Plainly 可抽离性、微信公众号复制的样式和图片持久性，从而锁定排版/剪贴板实现路线。

执行任务：
- [ ] 记录 Plainly 的 master 提交哈希、Node/pnpm/Rust 版本和现有测试基线。
- [ ] 绘制 Plainly 渲染路径：Markdown Parser → ThemeRegistry → HTML Transform → CSS Inline → Clipboard。
- [ ] 构建与实际桌面技术栈一致的最小 Tauri 2 + React 技术验证项目。
- [ ] 用明确输入参数调用 Plainly 主题与转换逻辑，输出 HTML；避免直接依赖旧 App/MobX/固定 DOM ID。
- [ ] 区分 Markdown 解析与依赖布局、计算样式的 DOM 排版，验证等待公式、Mermaid、图片尺寸和字体就绪后的异步输出；离线验证随包提供的渲染资源。
- [ ] 验证 clipboard HTML 与纯文本备用表示；区分「系统剪贴板写入成功」和「公众号保存草稿后图片仍存在」。
- [ ] 分别测试本地图片、公开 S3 图片 URL、HTML + Base64、HTML + PNG 剪贴板、多个 ClipboardItem、单图/多图及图文混排；这些都是候选实验，不预设可行。
- [ ] 记录 Windows 11 / macOS 的实际公众号后台兼容矩阵，包含系统、浏览器、图床域名类型、图片数量、域名可达性/防盗链、保存草稿后图片与样式是否保留。
- [ ] 建立至少 10 组渲染黄金样例（标题、段落、引用、表格、列表、代码、公式、流程图、多图、长图）。
- [ ] 验证输入后立即复制、切换主题或文章后立即复制，结果对应点击时的正文和主题，不复用旧结果。

**验收**：技术原型可运行；主题/转换组件可独立调用；异步渲染完成后才输出本次结果；兼容矩阵基于真实后台粘贴、保存、重新打开结果；形成默认复制策略及可用备用路径。

**交付建议**：tests/fixtures/wechat-copy/、docs/testing/wechat-compatibility.md；实际路径按最终工程布局决定。

- [ ] 构建 packages/markdown-core、packages/wechat-renderer、packages/shared-types、packages/editor-react。
- [ ] 从 Plainly 抽离 markdown-it 插件、主题定义、主题注册表、组件转换器、CSS 内联与公众号专用修正。
- [ ] 将 themeNum/templateNum 统一调整为稳定 themeId；处理缺失主题时回退。
- [ ] 排版函数使用正文、themeId、输出模式的固定输入，异步返回输入修订标识、HTML、警告和依赖素材；预览丢弃过时结果，复制使用点击时快照，失败不返回上次成功结果。
- [ ] 明确允许的 Markdown / HTML 语法；不可信 HTML 进入预览 DOM 前统一净化，覆盖编辑器、MCP 和导入入口，限制事件属性与资源 URL；最终导出不含调试标记或内部应用 URI。
- [ ] 建立前后端共享的素材引用样例：内联图片、引用式图片、HTML img src、已登记图床 URL；普通代码块/行内代码/转义文本不计图片引用。公式与 Mermaid 的源片段类型和源码生成相同 source_key，不使用整篇正文或主题指纹判断删除。
- [ ] 对数学公式、Mermaid、代码主题等较重扩展做缓存或按需加载。
- [ ] 建立单元测试、格式/类型检查和 CI 基础流水线。
- [ ] 整理版权、主题来源与许可证清单。

**验收**：排版包可以在独立测试环境运行；切换主题不改变源 Markdown；既有 Plainly 主题样例的输出差异有记录且符合预期；应用加载后能够离线渲染示例文章；不同内容入口不能通过预览执行脚本或绕过受控资源 URL 规则。

## 4. P2 SQLite 内容管理与 Obsidian 式桌面交互

### 4.1 Rust 领域模块

- [ ] SQLite 初始化、迁移、WAL、foreign_keys、错误码、事务包装、数据库完整性检查。
- [ ] entries 统一模型：idea/reference/article；标题、正文、状态、分类、标签、来源、版本。
- [ ] CategoryService：两级分类、排序、同级重名校验、删除重归类。
- [ ] TagService：创建、关联、规范化和过滤。
- [ ] EntryService：创建、读取、更新、软删除、恢复、分页、筛选。
- [ ] RevisionService：仅手动保存版本、AI 整篇覆盖前保留关键历史，每条目最多 3 份；自动保存不生成全文历史；乐观锁 expectedVersion。
- [ ] SearchService：FTS5 trigram；不足 3 字符使用参数化 LIKE 回退，搜索输入按普通文本处理，覆盖字面通配字符和分类/标签联合过滤。
- [ ] 初始化稳定 workspace_id；恢复备份时使用备份原有 ID，供 S3 图床与数据库备份划分命名空间。
- [ ] IPC：只暴露稳定 DTO，不直接返回数据库行对象。
- [ ] 内容关联：灵感/资料与文章的 entry_links。

### 4.2 前端

- [ ] 左侧导航：收集箱、资料库、文章库、搜索、素材、设置。
- [ ] 分类树与标签筛选，包含二级分类编辑。
- [ ] 中央多标签页：打开/切换文章、未保存状态、离开前保存提醒；只保证数据库已成功提交的正文。
- [ ] CodeMirror 6：源码编辑、Markdown 高亮、快捷键、查找替换、选区操作。
- [ ] 实时公众号预览、纯编辑/双栏/纯预览三种视图。
- [ ] 自动保存防抖、切换保存和失败提示；冲突时停止覆盖、保留内存内容，允许复制当前稿、另存草稿或重新加载；MCP 返回 VERSION_CONFLICT。
- [ ] 每篇文章最多一个在途保存请求，新输入合并待提交；响应关联本地修订号，不回填覆盖新输入。切换、失焦、正常退出共用保存队列，保存失败保留窗口供处理。
- [ ] 退出准备阶段暂停新编辑和服务写入；保存失败或取消退出时恢复编辑与服务，保留缓冲和撤销历史，实际决定退出后才结束编辑会话。
- [ ] 编辑器异步目标包含 entryId、本地修订号、范围和原文；切换标签保留对应编辑状态，关闭标签结束该编辑会话。图片位置使用编辑器已有映射，不自行实现范围合并算法。
- [ ] 从灵感/资料创建文章草稿，保留来源关联。
- [ ] 导出单篇 .md（此阶段可只含纯文本，带图导出由 P3 完成）。

**验收**：
- 离线独立运行；完全关闭应用再打开，正文、分类、标签和最近打开位置正确。
- 至少 5 万字中文长文可编辑与搜索；中文输入法组合输入不丢字符。
- 两个写入方基于同一版本并发更新时，仅一个成功，另一方得到明确版本冲突。
- 连续输入期间触发失焦、切换和退出时，保存请求串行、不自发冲突；旧响应不覆盖新输入，最新修订提交前不显示已保存。
- 使用 1000 篇约 5000 字文章并含 5 万字长文的样本，验证一字、两字、标点、中英混合和分类/标签组合搜索，记录耗时，搜索不阻塞编辑。
- 通过迁移脚本创建新库、升级测试库和重启加载；所有测试无数据损坏。

## 5. P3 素材库、图片粘贴与 S3 图床

- [ ] 建立 AssetService 与 AssetUrlResolver；支持稳定 asset:// 逻辑 URI。
- [ ] 实现剪贴板图片粘贴、图片拖入、多文件处理，绑定发起时的文章和插入位置；后续输入使用编辑器位置映射，原文档关闭或目标被删除后不插入其他文章。
- [ ] 校验图片文件头、尺寸与大小；按 SHA-256 去重，多个逻辑 asset ID 可共用一份哈希文件。远程位置按哈希和准确存储目标去重，清理任务也按哈希复用。
- [ ] Rust 使用现有 Markdown 解析器权威生成 entry_assets，并随正文事务更新；与前端共用 P1 语法样例，封面独立维护，保留历史按同样规则提取引用。
- [ ] 实现图片预览加载及可见的失败占位；本地图片无需 S3 即可显示。
- [ ] 建立 S3StorageProvider，支持 endpoint/region/bucket、上传/下载/删除、超时取消与错误归类；连接测试用应用创建的对象验证上传、读取和删除权限，清理遵循普通对象删除语义，不增加桶历史版本扫描。
- [ ] 图床公开域名与备份私有桶分开配置；凭据用操作系统密钥存储。
- [ ] 实现 upload jobs（queued/running/retrying/completed/failed）及任务状态 UI。
- [ ] 上传请求发出前登记工作区专属前缀内的确定性 object key 和准确存储目标，失败/取消保留映射。变更存储目标使用新配置，仍有未删除对象映射的旧配置及凭据引用保留；外部来源 URL 不登记为应用拥有的对象。
- [ ] 实现技术方案第 6.4 节退出流程：取消排队上传，结束在途素材任务；若仍有素材写任务或未正常结束的已发送上传，本次跳过整轮清理。其余情况在停止业务写入后一次计算引用，不增加按任务维护的素材保护表。
- [ ] 按哈希合并全部正文、封面、最多 3 条历史、可恢复软删除内容的图片引用，以及派生 source_key 引用；组内任何引用都保留整组。已登记公开 URL 也参与引用判断，外部源站原图不删除。
- [ ] 无引用组逐个删除尚未完成的已登记远程目标（含未确认上传成功的目标），记录每个目标结果；全部远程完成再删本地，本地完成才移除素材/位置记录并完成清理任务。取消该组待上传/补图项，不移除导入任务的其他结果；无文件占位只清理记录和对应补图项。
- [ ] 每次退出一轮尝试，失败/取消保留未完成项，允许停止余下清理直接退出。再次引用任一同哈希素材取消整组任务，保留已发生的远程删除结果，需要发布时只补传所选图床中缺少的对象；下一次退出仍先重查引用。
- [ ] 任务已结束且允许清理时，检查应用 assets/ 中无数据库记录的哈希文件；已有记录的文件遵循远程优先顺序，不扫描远程桶或外部目录回收孤立对象。
- [ ] 完成带图片的 Markdown 压缩包导出：改写素材 URI 为相对路径，导出文章元信息与对应图片。
- [ ] 素材缺失时提示；数据库恢复后可使用已有图床远程 URL 读取，纯本地图片不保证恢复。

**验收**：
- 无网络状态粘贴截图、保存、重启后正常展示。
- 同图重复粘贴不会生成多份相同原始文件。
- S3 故障不导致正文丢失；上传成功后 Markdown 正文仍使用稳定资源标识。
- 图片删除、撤销、共享引用、退出取消和 S3 失败重试按第 10.3 节 G01～G09、G11～G13 验收；P4 完成后补齐 G10 派生图片联调。
- 异步粘贴返回时切换文章，不会插错文章。
- 解压 Markdown 导出包后，普通 Markdown 阅读器可显示图片。

## 6. P4 微信公众号文章导入与发布

### 6.1 公众号导入

- [ ] 识别公开 mp.weixin.qq.com URL，规范化并去重。
- [ ] 正式实现前确定 HTML 提取/转 Markdown 的运行位置和依赖，复用成熟解析器；MCP 导入使用同一个 ImportService，不能依赖用户当前打开的编辑标签页。
- [ ] 安全网页获取：限制协议、目标地址、重定向、请求大小和超时。
- [ ] 提取文章标题、公众号、作者、发布时间、正文及图片。
- [ ] 下载图片至 AssetService，将 HTML 净化并转换为 Markdown。
- [ ] **只保存清洗后的 Markdown 和来源元数据**；原始 HTML 解析后丢弃，不保存原始快照或自动生成原文版本。
- [ ] 任务支持成功、部分成功、访问受限、失败诊断与按需重试。
- [ ] 失败图片保留稳定 asset:// 占位；jobs 只记录目标条目、asset ID、原图片 URL 和错误。补图仅填充素材，不覆盖正文；所有引用已删除则跳过，其他内容仍复用该占位时继续补图。同一任务重试复用结果条目，不重复创建。
- [ ] 规范化来源使用唯一记录，重复 URL 打开已有内容；首版失败重试只补失败部分，不增加静默整篇覆盖或自动创建副本。
- [ ] 导入默认进入 reference，支持由资料创建 article 并保留来源关系。

### 6.2 公众号导出

- [ ] 使用 Plainly 排版核心生成主题 HTML 和内联 CSS。
- [ ] 完成 HTML 文件导出：内联 CSS，素材复制至相对 assets/，带图时打包；Markdown 单文件导出提供配套图片目录，带图包独立包含素材，均不修改数据库正文。
- [ ] 导出固定输入并等待渲染完成；远程素材通过资源服务下载后放入导出包，缺失明确报告；验证导出包不依赖应用素材目录或日后仍有效的图床 URL。
- [ ] 无图床时提供正文样式复制和按顺序逐张图片辅助上传。
- [ ] 有图床时把 asset:// 替换为稳定公开 URL，尝试整篇复制。
- [ ] 对代码块、表格、公式和 Mermaid 等做目标兼容输出；公式/图表的派生图片沿用 AssetService，不改写原 Markdown。
- [ ] 为派生素材登记源片段类型与源码对应的 source_key；退出时从全部正文和保留历史提取源片段决定保留。移除“最近有效导出”关联和整篇输入指纹淘汰规则；重新导出不提前删除旧图，仍被源片段引用的主题版本可以保留。
- [ ] 发布前检查缺失素材、图床 URL 可达性。
- [ ] 用户可记录发布状态、封面、摘要和公众号原文 URL。

**验收**：
- 公开公众号文章导入后能离线编辑清洗后的正文，数据库中不保存原始 HTML 或导入前版本。
- 十图文章部分下载失败后修改正文，再补图：正文修改保留、图片就位、条目不重复；用户删除的占位不被补图任务重新插回。
- 无图床时有明确的图文发布路径；有图床时多图复制以实际公众号后台保存并重新打开结果为准。
- 导入失败、图片缺失、复制失败不会影响已经保存的文章正文。
- HTML / Markdown 导出包解压后可在普通浏览器或阅读器离线显示图片；源素材后续被清理不影响已导出的文件。
- 派生图来源仍在时保留本地和远程图片；覆盖普通改字、换主题、重新导出后撤销及仅历史仍含源片段的场景，见 G10。

## 7. P5 MCP 服务与 AI

### 7.1 MCP

- [ ] 采用官方 Rust SDK rmcp 接入 Axum，锁定依赖和支持的协议版本，由 SDK 处理初始化、协商和传输；回环地址启动 Streamable HTTP 服务，设置支持启用/停止、端口和访问令牌。
- [ ] 鉴权：请求令牌、Origin 验证、read/write 权限、输入长度限制和日志脱敏。
- [ ] 开放 list_entries、search_entries、get_entry、create_entry、update_entry、list_categories、list_tags、import_wechat_article、get_job_status。
- [ ] MCP 工具通过 Rust 领域 Service 执行，而非直接执行 SQL。
- [ ] update_entry 必须传 expectedVersion，冲突返回结构化错误与当前版本。
- [ ] 测试本机 Codex / Claude Code 客户端接入路径；版本协商和错误格式按使用的协议规范实现。
- [ ] 正常退出或恢复时停止接收写请求并结束旧连接；数据库恢复后客户端重新读取正文与版本再写入。

### 7.2 AI

- [ ] 模型供应商设置：自定义接口地址、模型名、密钥、超时。
- [ ] Rust 统一 AIService，支持错误处理、取消、重试和任务记录。
- [ ] 完成文章摘要、公众号标题建议、选区改写三类操作。
- [ ] 结果先展示候选与差异；确认后检查发起时的 entryId、编辑修订与范围，使用编辑器事务应用并走普通保存队列。正文变化或原编辑会话关闭时保留候选供复制或重做，不替换当前新选区。
- [ ] 选区改写支持编辑器撤销；AI 整篇覆盖前的最多 3 条历史规则保留，首版不新增整篇重写功能；重启不自动重发 AI 请求。
- [ ] 对输入的导入文章/外部资料采用数据隔离，不让其内容提升工具权限。

**验收**：
- 只读令牌不能调用写工具，无效令牌、异常 Origin 和非法参数被拒绝。
- MCP 同时写同篇文章时遵守 SQLite 版本控制。
- AI 调用失败不改变文章；选区改写可通过撤销恢复，整篇替换前的关键历史最多 3 条。
- AI 等待期间继续输入、改变选区或切换文章：结果不会覆盖新输入或其他文章；正文未变时应用到原范围，正文变化时仅保留候选。

## 8. P6 SQLite 数据库 S3 备份与恢复

- [ ] 使用 SQLite Online Backup API 生成单文件一致性数据库快照。
- [ ] 数据库快照执行 integrity_check 与 foreign_key_check，上传到配置前缀下 `wechat-creator-workbench/<workspace_id>/backups/`。
- [ ] S3 对象列表展示备份；新快照成功上传后在选定工作区内保留最近 5 个成功快照，其他工作区与无关对象不参与删除。新设备可选择已有工作区备份目录。
- [ ] 备份文件仅为 SQLite 数据库，不收集本地图片、附件、原始 HTML 或其他工作区目录。
- [ ] 恢复文件先在 staging 校验完整性、外键和 schema；受支持旧 schema 在临时副本迁移并检查基本查询，失败保留当前库。
- [ ] 按技术方案第 8.2 节实现重启恢复：停止新写入与任务、处理待保存稿、等待在途任务、记录待恢复标记，正常关闭连接和 WAL，再重启；此次退出跳过图片清理。
- [ ] 启动服务前完成替换，保留一份临时旧库供本次失败回滚；重开并验证成功后清除标记和旧库。启动发现未完成标记时先处理本次恢复，不额外设计多代副本或恢复框架。
- [ ] 恢复后重建编辑器，旧缓冲与 AI 候选失效；旧上传、导入任务停下供用户重试，AI 不重发，旧清理任务丢弃；下一次正常退出按恢复库的引用重新判断素材清理。
- [ ] 恢复后文章正文、分类、标签、少量历史与图床地址映射可读。
- [ ] 本地图片若不存在，支持从记录的图床 URL 加载；无远程图床副本时清晰提示缺图。
- [ ] 不将 S3/AI 密钥明文写入数据库，恢复后需要重新授权时提供设置入口。
- [ ] 测试备份上传中断、损坏数据库、较新 schema、恢复中断、无本地图片的新设备恢复。

**验收**：
- S3 备份每次只有一个 SQLite 数据库对象，默认保留最近 5 份，备份/恢复能够直接在应用界面操作。
- 新设备能够恢复数据库全部正文与元数据；图床地址可用时可以加载远程图片，不承诺恢复仅存本地的图片。
- 数据库校验失败不会覆盖当前正常库。
- 恢复时存在未保存稿、运行中的导入/上传或 AI 请求：完成切换后不会把旧状态续写进恢复库，恢复重启不清理图片；MCP 重新连接并读取后可以正常修改。
- 替换过程失败或中断时，下次启动处理同一次恢复并可回到旧库；只保留一份临时回滚副本。恢复已清理图片对应的旧快照时提示缺图，不重放旧删除任务。

### 10.2 建议质量门槛

- Rust 领域服务中所有关键状态转换有单元测试或集成测试。
- 文章、标签、分类、素材引用及版本号依赖数据库约束与事务；正文引用为权威数据，entry_assets 由保存过程重建。
- 用户确认已保存的正文在强制终止/重启后完整。
- 同一文章串行保存，异步结果不覆盖新输入或其他文章；素材物理清理不发生在可撤销的编辑会话内。
- 正常退出的素材清理以本地文件和全部应用管理的 S3 对象删除为完成条件；网络失败可追踪且保留本地文件，不靠吞掉错误或无限重试完成退出。
- 无 S3/AI 时完整完成本地写作；关闭网络不影响已保存素材预览。
- 公众号粘贴成功与否以真实保存草稿重开结果为准，不使用复制 API 返回值代替。
- 本文列出的实际失败场景具有清晰错误提示和可重试或人工处理入口；不为理论上的所有异常增加兜底和自动恢复。

### 10.3 图片生命周期专项验收

以下均为待实现后的验收项。自动化用例检查引用、任务和请求顺序；另在实际 S3 兼容服务上验证上传、读取、删除权限及对象接口结果，不能以模拟测试代替远程验收。默认以无版本控制的测试桶检查物理删除；桶自行保留的历史版本与 CDN 缓存不属于应用清理范围。

| 编号 | 操作场景 | 必须观察到的结果 |
| --- | --- | --- |
| G01 | 删除正文图片 → 自动保存 → 撤销，再重做并正常退出 | 编辑会话内两端始终保留；退出时按最终已提交引用决定清理，撤销不依赖网络 |
| G02 | 保存失败或取消退出 | 不开始任何物理删除，保留正文和撤销历史，恢复编辑与服务；关闭单个标签也不触发清理 |
| G03 | 同图跨文章、封面、关键历史、软删除条目或不同 asset ID 复用 | 任一引用存在就保留整个哈希组；最后引用消失后，在远程可用且任务已结束的退出中两端均删除，远程每个目标只处理一次 |
| G04 | 无引用图片有两个远程位置，其中一个删除失败 | 成功目标记已删除，失败目标保留，本地文件和素材记录保留；下次退出只尝试剩余目标，不误报整组完成 |
| G05 | G04 之后重新插入同一文件、新 asset ID 或已登记图床 URL | 取消同哈希组清理，离线可用本地图片；已删远程地址不冒充可用，发布时只补传所选图床缺少的对象 |
| G06 | 远程已全部删除，本地删除失败 | 保留本地失败状态及素材记录，下次无引用时只补本地删除，成功后才移除整组记录 |
| G07 | 上传排队或正在上传时退出 | 排队上传取消；发送前已有准确目标记录。存在未结束素材任务或已发送上传未正常结束时跳过本轮清理，不并发上传/删除同一对象；后续退出可以清理登记目标 |
| G08 | 清理进行到一半取消，或远程返回权限错误/超时 | 停止剩余清理并退出，不返回已失去部分素材的原撤销会话；保留逐目标结果。错误不当作不存在，不无限重试 |
| G09 | 用已登记 S3 URL 引用图片；另导入外部来源图片 | 已登记 URL 计入引用并保护对应组；外部来源图片只清理应用本地/图床副本，绝不向来源站点删除原图 |
| G10 | 公式/图表导出后改其他段落、换主题；导出新源码后撤销回旧源码；源片段只在历史中存在 | 以源片段 source_key 而非整篇正文指纹保留原图。源片段与图片直接引用全部消失后才在正常退出清理；导出文件自身的图片副本不受影响 |
| G11 | 部分导入形成无文件占位；取消插图留下未登记哈希文件 | 无引用占位连同对应补图项移除，不请求 S3；允许清理时只移除应用 assets/ 内无记录哈希文件，有记录且远程删除失败的本地文件不能被此步骤绕过删除 |
| G12 | 图床配置变更、删除权限不足 | 连接测试包含删除权限；旧对象仍使用原存储目标，尚有关联的旧配置不能直接删除；凭据不足明确失败并保留待处理目标 |
| G13 | 强制结束应用后重新打开 | 不要求强制退出完成清理；旧清理任务不自动执行，下一次正常退出先依据当前引用决定，新增引用不会被旧任务删除 |
| G14 | 恢复数据库触发重启、再恢复含已删除图片的旧快照 | 恢复前不清理图片，旧清理任务不重放；下次退出使用恢复库引用，已经两端删除的图片显示缺失，不宣称可由数据库恢复 |
