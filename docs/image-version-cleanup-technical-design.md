# 图片旧版本清理技术方案

状态：实现与验收见[实施说明](./image-version-cleanup-implementation.md)及[验收记录](./image-version-cleanup-validation.md)。清理由后台自动判断和执行，不要求用户勾选或确认；部署单独记录。

## 1. 目标与边界

清理多次图片编辑产生的闲置衍生成品，保留原图、当前版本、仍被引用的历史版本及已用于发布的图片。清理必须能够解释保留或删除的依据，并在有限期限内恢复已回收的成品。

采用“引用保护、历史保留、自动等待、延迟执行、删除前复核”的流程。公开图床、本地文件和同步私有对象分别判断，不把删除一条版本记录等同于删除所有存储副本。

首版不提供以下能力：

- 扫描整个存储桶并按文件年龄批量删除。
- 仅凭当前文章正文、文章状态或 HTTP 状态推断图片没有外部用途。
- 自动解除已发布、已外发及历史来源不明图片的保护。
- 为了释放空间覆盖旧图片地址、改写旧成品快照或复用已删除对象的身份。

公开链接可能在应用之外被使用，不能通过本地数据库或爬取文章穷尽证明其未发布。对已知外发对象和无法确认外部用途的对象，默认保留；已发布图片不进入本清理流程的可删除集合。

## 2. 当前实现与需要补齐的能力

| 当前事实 | 设计影响 |
| --- | --- |
| 每次提交生成独立 `image_render` 与输出素材，成品快照不可修改 | 版本清理不能通过覆盖旧快照完成 |
| 输出素材的 `kind` 也是 `original`，通过 `source_key=image-render:<id>` 及成品关联识别 | 不得仅按 `assets.kind` 判断原图和衍生图 |
| `referenced()` 将全部成品、工程和暂存依赖纳入保护 | 必须区分“保存历史元数据”和“历史输出字节必须常驻”，否则没有旧版本能被回收 |
| `asset_locations` 的插入与更新都会写入 `asset_public_protection` | 现有保护不能证明实际发布情况，历史记录必须继续保守保护 |
| 本地未引用素材有七天宽限，且有图床位置记录的素材不进入现有删除组 | 不能把现有七天机制直接扩展为远端旧版本删除 |
| 同步协议 3 不允许删除不可变成品，私有 blob 也没有回收接口 | 远端清理需要单独的生命周期协作，不能由本机直接推断和删除 |
| 同一字节哈希可以对应多个逻辑素材、版本和文章 | 最终按物理文件或对象汇总引用，任一用途仍存续就保留共享字节 |

## 3. 保留规则

保护优先于数量和时间限制。以下任一条件成立，都不得删除对应版本所需的字节及其依赖。

| 类别 | 保留范围 | 解除条件 |
| --- | --- | --- |
| 原图与输入素材 | 工程原始图片、导入的非衍生图片、原始背景文件及来源不明的输入文件 | 本方案不清理；以旧成品作输入时按依赖版本规则保护 |
| 当前使用 | 正文、封面、专题图片与文本、当前工程、当前应用版本 | 引用真实移除后重新计算，不能直接删除 |
| 依赖版本 | 作为另一工程的基底、图层或背景使用的旧成品 | 全部下游依赖移除后重新计算 |
| 已发布或外发 | 已发布文章的历史图片，以及通过应用交付出去的公开图片地址 | 本方案不自动解除 |
| 恢复与在途状态 | 文章历史、编辑恢复、冲突副本、会话撤销、输出暂存及同步队列 | 对应状态按既有规则结束，随后进入新的宽限期 |
| 备份 | 已登记备份引用及用途无法核实的备份保护 | 备份保留策略明确到期并完成登记，不由版本清理器擅自解除 |
| 人工保留 | 用户明确保留的版本 | 用户解除保留后仍需满足其他规则 |
| 最低历史 | 每个工程最近 5 个已提交成品 | 超出数量不代表立即可删除 |
| 新近版本 | 创建时间不足 30 天的成品 | 满 30 天后仍需满足全部条件 |

“最近 5 个”按成品提交时间及稳定 ID 排序，不按文件修改时间；当前被引用的更老版本额外保留。5 个和 30 天是首版产品建议，不是存储服务的统一标准，也不要求首版增加配置项。

只有同时满足“可确认是衍生成品、不属于任何保护集合、不是最近 5 个、已创建满 30 天”的版本，才能列为候选。旧版本与原图字节相同，或多个版本共享同一物理对象时，仍按全部关联用途的并集判断。

工程的 `base_asset_id` 可能指向旧成品，必须递归追踪；以工程、成品与素材身份去重，不能只扫描最新工程的一层 `assetIds`。

## 4. 已发布图片与外部用途保护

### 4.1 不可逆推的历史数据

升级时将现有 `asset_public_protection` 及已存在图床位置记录标记为“历史用途不明，保留”，不批量清空，不根据文章当前的 `publishedUrl`、已发布状态或正文内容倒推其从未对外使用。

已删除文章、撤回发布状态、修改发布链接或正文换图，都不能解除过去的发布保护。当前文章副本不是已发布页面的历史快照。

没有足够证据的历史图片，第一版只展示保留原因，不提供普通清理入口的强制删除选项。因此首版可能无法回收已有图床中的旧版本；这是保证历史文章安全的明确边界，不能将这部分空间计入预计可释放容量。

### 4.2 为新版本记录真实用途

区分“自动上传完成”和“公开地址已经交付给外部”。新版本仅自动上传、未对外使用时，可以在满足保留规则后成为候选。以下动作须对最终输出中实际使用的图片地址建立长期保护：

- 复制公众号格式、含图片链接的 Markdown、HTML 或图片地址。
- 导出包含公开图片地址的文章或文件。
- 发布、更新已发布文章，或将文章标记为已发布时记录该次图片集合。
- 应用能识别的其他公开地址外发动作。

记录的是每次输出或发布时的图片集合，后续修改正文不会覆盖这份集合。保护绑定实际存储位置及其内容身份，同时关联逻辑素材、成品、文章和外发时间；同一图片的历史域名、不同 URL 别名及 `wcb-image` 逻辑身份都需要归并。

只交付图片字节且确定不包含图床 URL 的操作，不因该操作单独锁住图床位置；无法判定实际剪贴板或文件载荷是否包含公开 URL 时，按外发保护处理。不能仅依据按钮名称判断。

### 4.3 保护必须先于外发

含可清理图床地址的输出，先持久化并确认保护，再交付给剪贴板、导出文件或发布接口。输出失败可以多保留一条保护，不能先交付地址再异步补保护。

开启跨设备同步时，外发保护需要同步服务确认后才能输出可清理对象的公开地址；如果无法联网确认，可继续编辑、保存草稿或输出不包含该地址的图片字节，但不能绕过保护直接外发。单机工作区则由本机的同一生命周期协调器先确认保护。

应用外手工取得图床地址并另行发布无法全面观测。已外发、历史来源不明和不能证明归属的对象自动保留；不能以用户确认代替安全条件，也不能将这些对象批量转为可删除。只有完整接入登记、引用与外发保护的新托管成品，才可自动进入远端候选。

## 5. 引用计算与物理对象身份

### 5.1 统一计算保留集合

沿用现有 Markdown、HTML、封面与专题引用解析，补充以下保留入口：

- 当前及仍在保留期的文章历史、恢复记录与冲突内容。
- 活跃工程的原图、全部图层、背景、工程基底及其递归成品依赖。
- 当前应用版本、最近 5 个版本、人工保留和发布保护的成品快照。
- 输出暂存、会话撤销、未提交变更及上传下载任务。
- bootstrap、inbox、outbox、待确认操作及已登记备份。

普通历史成品元数据的存在，不再独自成为“输出字节永久保留”的入口；只有从上述保留集合可达的成品及其依赖才要求常驻。原始输入文件始终保留，不能借此清理原图。

页面上看不到图片、当前文章不引用图片、公开 URL 暂时返回 404，都不是解除保护的依据。解析失败、同步引用不完整或备份保护不明时，该次清理暂停并说明原因，不用空引用集合继续删除。

### 5.2 按实际删除对象归并

本地文件按字节哈希及实际路径归并。同步私有 blob 按服务实例、工作区和哈希判断；桶被多个实例共享时，还需要明确的全局归属与引用登记，未具备时不能开启远端永久删除。

图床按存储服务、桶、实际对象键及可用的对象版本归并。存储配置 ID 和公开 URL 不是唯一物理身份；配置复制、更换域名或同对象多条位置记录，不得绕过保护。

分别保留源文件哈希与上传后的 `content_sha256`，压缩上传可能改变字节。ETag 不替代内容哈希。任何关联资产或历史地址仍有用途，都不能删除共享的图床对象。

只处理本应用登记且归属明确的对象。不扫描无关前缀，不接管其他应用写入的文件；原配置失效、凭据缺失、对象被外部改写或归属冲突时，保持原状并终止该对象的清理。

## 6. 清理与恢复流程

### 6.1 自动扫描与状态

扫描生成有版本号的清理计划，不立即删文件。每项展示缩略图、所属工程、版本时间、占用位置、实际可释放空间，以及保留或入选原因。

按物理对象去重计算容量，不将被其他版本共享的字节重复累加。分别显示本地、图床与同步存储预计释放量；备份字节单独计入，不把“移入回收区”宣传为已经释放空间。

后台按当前引用重算候选。窗口只查看待清理、保留原因与回收记录，提供保留和恢复操作；不提供确认清理或选择待删除对象的步骤。

### 6.2 延迟执行

满足全部保留与协作规则的候选自动进入 7 天待清理期。此期间保留原文件和原公开地址，用户可选择保留；新引用、发布保护、人工保留或同步变化使候选失效时，自动取消该项并重新开始引用核对。

待清理期结束后，再次验证引用、保留数量、对象身份和跨设备条件，取得该物理对象的独占执行资格。扫描结果不是永久删除凭证。

### 6.3 删除前备份与执行

永久移除原存储位置前，必须具有已落盘并校验通过的字节备份及恢复清单。仅有数据库、文件名或 URL 不算字节备份。备份放入独立的受保护回收区，不能和原对象一并被同一清理规则删除；备份失败或空间不足则不执行删除。

恢复清单包含逻辑素材与成品身份、源/上传后哈希、原存储目标及对象键、公开地址、可用的对象版本标识和实际备份位置，不包含存储访问密钥。公开图床字节可能与本地成品不同，需保存实际上传字节。

本地文件、图床文件和同步私有对象分别执行与记账；一个位置失败不伪装为全部成功。回收备份确认前不删除原位置，原位置清理期间保留至少一份已校验备份。首版逐对象执行，不用批量删除接口掩盖部分失败。

回收区专用备份只保护回收副本，不视为对已确认候选原位置的新业务引用；普通工作区备份的保护仍按第 3 节执行，不能利用回收区的到期时间绕过。

删除后仍保留不可变成品元数据、历史操作回执和生命周期记录，标明输出字节的状态；这不意味着这些元数据继续无条件保护已退休的输出文件。不得通过删除快照行、修改快照内容或重写原操作回执规避现有约束。

### 6.4 恢复期限与不确定结果

移除原位置后，回收区的字节再保留 30 天。期间恢复时先校验字节，再恢复存储与可用引用，最后结束恢复任务。30 天之后才可清除没有任何新保护的回收备份。

远端对象开始清理后，原物理键永久退休。删除超时或进程中断时，记录为结果待核对，不能计为释放成功；恢复一律写入新 generation 和新物理键，校验后重新绑定逻辑身份，避免迟到的删除请求删掉恢复文件。本地同步文件操作不存在迟到的网络请求，可在同一工作区锁内恢复原路径。

回收备份到期后不承诺逐字节恢复旧成品。即使原图和场景都在，新版编码器或渲染器也可能产生不同字节；重新生成应创建新的成品身份和地址，不覆盖旧快照。

## 7. 跨设备同步与并发

### 7.1 谁可以批准远端删除

有同步的工作区，由同步服务协调版本退休与远端删除资格；本机不能凭自己的正文扫描直接删除图床或私有 blob。单机工作区由本机统一协调，不启用独立的服务端删除者。

远端清理开启前，所有未撤销设备都必须支持这套生命周期能力，完成自己的未提交内容、恢复、历史和备份保护上报，并确认服务端指定的完整引用检查点。依据服务端游标与确认记录判断，不能用“最近在线过”或固定等待天数代替。

任一设备离线、仍有待确认操作或引用扫描未完成，默认阻止工作区的远端永久删除；本地保守清理仍可单独运行。用户撤销设备是独立的设备管理动作，清理器不能为了通过检查自动撤销设备。撤销后该设备的离线稿不再被云端完整掌握，需先导出或迁移，不能声称离线数据已经安全。

### 7.2 删除与新增引用不能穿插

计划记录扫描时的引用版本。执行前以服务端或本机统一协调器做原子校验，只有引用版本、对象身份及候选状态仍匹配，才进入执行中。

进入执行中后，发布、正文恢复、工程引用、上传及迁移等入口不能直接重新使用该对象；需要先取消尚未启动的删除，或等待已启动操作结束并完成恢复，再提交新引用。数据库与对象存储之间不存在共同事务，要用持久化任务状态协调，不能在发出网络删除后就释放资格。

重试复用同一任务身份，只处理原对象。对象已不存在时仍需确认任务目标及备份，不通过重复扫描生成另一个范围更大的删除任务。过期或失去资格的执行器不能重新发起删除；存在在途操作的不确定结果时，按第 6.4 节保持阻塞。

### 7.3 兼容旧设备、备份与重放

协议 3 通过可选 `imageVersionGc: 1` 能力扩展生命周期，客户端与服务端成套升级。旧设备不能确认检查点，因此阻止远端回收；已经采用托管物理映射及退休历史的工作区不能直接回滚旧服务端或依赖旧客户端重建完整历史。`image_render` 的不可变约束继续保留。

生命周期作为独立、可同步的状态存在，不能修改原始场景或成品快照。bootstrap、暂停后重建、工作区迁移、备份恢复以及旧回执重放都要读取该状态。

服务端依赖校验、blob 读取和客户端素材解析需要区分活跃、可恢复及已清理状态。不能只删除 R2 文件，却继续把对应输出标记为正常可用；历史元数据存在也不能继续成为所有退休输出字节的永久保留入口。在服务端尚未支持生命周期前，不放松当前对已同步素材的保护。

旧回执的“已应用”仅说明过去的操作成立，不代表其文件永远存在，也不能自动复活已清理的输出。恢复旧备份或离线稿时先核对生命周期，需要字节时从回收区或现有已校验副本恢复；无法恢复则保留用户内容并明确反馈，不静默丢图，也不覆盖新的同步基线。

## 8. 存储服务适配约束

不把桶级生命周期规则直接配置为清理工作区图片。桶规则不知道文章、已发布地址、共享字节和跨设备状态，最多用于清理应用明确管理的回收区到期副本。

不能把 S3 版本控制视为业务回收站：普通删除可能创建删除标记，旧字节仍然占空间，而原公开链接已无法正常访问。是否删除特定对象版本，应按提供者能力与清理计划明确决定。[Amazon S3 DeleteObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_DeleteObject.html)

不同 S3 兼容服务的条件删除能力不等同。Cloudflare 当前条件操作文档列出的是特定写入操作，不能据此推断 `DeleteObject` 具有相同原子条件。实现前对每种服务核验；支持时使用条件或对象版本约束，不支持时仅处理本应用独占管理、不可覆盖的对象，并由统一执行器协调。无法确认独占归属或对象版本的目标，不进入远端自动删除。[Cloudflare R2 条件操作](https://developers.cloudflare.com/r2/api/s3/conditional-operations/)

新对象采用不可覆盖的键，重复输出按已确认的相同内容复用，新内容一律分配新键。远端恢复使用新物理键和代际，不复用已退休键。启用了对象锁或服务端拒绝删除时，保留失败状态，不尝试绕过存储端限制。

## 9. 概念数据与代码边界

以下仅定义职责，不是已确定的数据库迁移或接口报文。

| 数据职责 | 保存内容 |
| --- | --- |
| 原图及版本关系 | 原始输入身份、所属工程、输出成品、递归依赖 |
| 用途保护 | 保护原因、逻辑及物理对象身份、外发/发布集合、来源文章、时间及同步确认状态 |
| 生命周期 | 活跃、候选、待清理、执行中、已移除、恢复中、已恢复及结果待核对；配套引用版本和任务身份 |
| 回收清单 | 校验后的字节备份、存储目标、原位置、删除结果与备份到期时间 |
| 设备确认 | 能力版本、引用检查点及待确认工作是否清空 |

保护理由可以并存，不以一个布尔值覆盖所有来源。文件缺失不能通过删记录掩盖；清理日志记录对象身份、依据和真实结果，不记录访问密钥。

本地复用 `assets/cleanup.rs` 的引用计算、生命周期锁和候选思想，给旧版本清理增加明确入口；上传队列不承担全局垃圾回收。`image_canvas.rs` 保持原图和成品身份语义，允许在显式生命周期下释放闲置输出字节。

保留 `assets`、`image_renders` 及其关联的逻辑身份，只记录副本可用性与生命周期变化。旧版本字节回收不能直接套用现有删除整组 `assets` 行的路径，以免破坏外键、历史快照和同步回执。

发布及剪贴板/导出边界负责先登记保护；同步层负责保护与生命周期状态传播；服务端负责引用检查点及删除资格；存储适配层只对指定对象执行和校验，不自行决定业务可删性。

## 10. 实施顺序

| 阶段 | 交付内容 | 开启条件 |
| --- | --- | --- |
| 1. 识别与预览 | 原图/衍生图分类、递归引用扫描、保留理由、去重容量报告 | 只读，不能删除；先验证历史对象全部保持保护 |
| 2. 保护与单机回收 | 新外发保护、历史保护迁移、本地待清理及字节备份恢复 | 原图、历史图床及已发布图片均不受影响；先开放未上传图床且未进入同步的本地闲置衍生成品 |
| 3. 跨设备协调 | 能力协商、完整引用检查点、生命周期同步、恢复与旧回执闭包 | 全部未撤销设备升级且完成确认，否则远端删除保持关闭 |
| 4. 公开图床及私有对象回收 | 位置级去重、存储能力验证、自动等待、延迟执行与恢复 | 仅明确归属的闲置衍生成品；用途不明自动保留；先在隔离环境验收再开放 |

按已授权范围分阶段实施，验证达到对应门槛后继续。不得先解除全量保护，再等待后续阶段补齐发布登记或同步协调。

## 11. 验收矩阵

| 场景 | 必须结果 |
| --- | --- |
| 多次编辑同一图片 | 原图不进入候选；当前版本和最近 5 个版本保留 |
| 超过 30 天的闲置旧成品 | 符合全部条件时自动进入 7 天待清理期，删除前再次核对 |
| 旧成品成为另一工程的输入或背景 | 递归依赖保护生效，取消候选 |
| 多版本相同字节或多篇文章共用 | 任一引用仍在，物理文件/对象均保留，容量不重复统计 |
| 标记发布后正文换图、撤回状态或删除文章 | 历史发布图片及其原公开地址继续受保护 |
| 复制链接/公众号格式后尚未登记发布 | 外发保护先于输出，旧图不进入候选 |
| 外发登记失败或离线 | 不交付未受保护的可清理地址；用户草稿保留 |
| 历史已上传但发布情况未知 | 不自动解除旧保护，不要求用户确认后强删 |
| 含代码示例的 Markdown、HTML、URL 别名及图床域名更换 | 按实际用途解析并归并，既不漏真实引用，也不把示例错误当作实体图片 |
| 文章历史、恢复、冲突、备份或在途输出仍使用图片 | 对应保护均生效，不只扫描当前正文 |
| 离线设备、有未确认操作或旧版设备 | 阻止远端永久删除，不将“等待七天”视作确认 |
| 扫描后新增引用或发生发布 | 旧计划失效；开始执行前取消，已开始时先恢复再允许引用 |
| 删除超时、进程崩溃、失去执行资格 | 不伪报成功，不重复扩大删除范围，不与原址恢复穿插 |
| 已移除对象恢复、回收备份过期、旧备份导入 | 按各自恢复边界处理，不承诺无字节也能还原原成品 |
| 压缩上传、更换配置、多个位置指向同一对象 | 用实际上传字节和物理身份核对，不能因配置 ID 不同误删 |
| 备份损坏、空间不足、凭据缺失、对象锁或外部改写 | 停止对应删除，保留原对象或已验证副本及可定位结果 |
| Windows/macOS、Node SQLite/Workers D1、不同 S3 兼容服务 | 分别验证本机协调、服务端事务与真实对象语义，不能以一个环境替代全部验收 |

所有真实删除验收使用隔离工作区、独立对象前缀及测试文件。既有生产文章和图床不作为清理测试样本。
